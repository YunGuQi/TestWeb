# 小红书图文文案生产线 (XHS Note Operator)

本技能管辖小红书图文笔记文案全流程：文案构思、多模式编排、SSOT真源雷达数值与金句对齐、真人网感塑造，以及智能合规机审自愈（Red ➔ Green）。

> [!IMPORTANT]
> **【四大操盘机制与核心 Leading Words】**：
> 1. **SSOT（单一真源）**：数据源唯一定位目标测试画像（`docs/测试画像.md`）与核心结果定义（`lib/*-data.ts`），结果名、雷达数值、金句必须 100% 对齐真源，严禁主观编造假数据与假金句。
> 2. **Gate（刚性闸门）**：两处停机确认（范围与执行体定夺、全批机审绿灯交付），未获确认严禁越级推进。
> 3. **WeChat-Voice / Casual-Chat（微信闺蜜原声体）**：大白话、真吐槽，像微信语音转文字。带 1~2 句日常对话原声，前 3 行接住生活实物钩子；每行有主语+动作因果；聊完即停吐一口浊气。**严禁【中学生作文】**（假懂事/思想汇报/套“其实…反倒…”公式）；**严禁【文艺小说】**（堆砌环境修辞、镜头感等假深沉）。
> 4. **Red-to-Green Loop（机审闭环）**：文案落盘前必跑 `refine-notes.js`，直至 0 违规全绿灯交付。

## 文案编排与源头机审工作流

### Step 1: 画像与结果核对 (Audit SSOT)
- **动作**：查阅目标测试 `docs/测试画像.md` 与核心数据文件（`lib/*-data.ts`），提取品牌词、品类词、情绪四档、真实结果名、真实雷达维度与分值、以及官方原版金句。
- **完成判据**：明确该测试合法结果集合与专属品牌/品类标签，完成 SSOT 锚定，严禁凭空生造未在代码库中登记的数值或口号。

### Step 2: 交互闸门定范围与执行体 (Gate 1)
- **动作**：停机向大哥汇报并确认三项：
  1. 产出维度：单一测试（`design/product-docs/<测试名>/docs/`）或跨测试组合；
  2. 产出路线：发放率打底 / 人工定指定结果 / 全量结果覆盖；
  3. 执行体委派：是否使用子代理执行文案编排。
- **完成判据**：获得大哥明确指令。未获确认不得启动 Step 3。

### Step 3: 工作包与分配表生成 (Make Workpack & Plan)
- **动作**：执行脚本生成批次规约，自动轮转 5 大生活场域与 60+ 针眼道具：
  ```bash
  node ".agent/skills/xhs-note-operator/scripts/make-workpack.js" --test <测试名> (--pick 6 [--seed auto] | --results r1,r3,...)
  node ".agent/skills/xhs-note-operator/scripts/make-plan.js" --test <测试名> (--pick 6 [--seed auto] | --results r1,r3,...)
  ```
- **完成判据**：工作包与分配表落盘，各卡片取型（模式/取材型/展开型/档位/针眼道具）无同构冲突。

### Step 4: 逐篇正向撰写 (Execute Casual-Chat Writing)
- **动作**：对照分配表与 [`references/01_双位与正文.md`](references/01_双位与正文.md)、[`references/01_场景与道具库.md`](references/01_场景与道具库.md) 逐篇落笔：
  1. **双位分工**：
     - 封面管认领：纯色大字，2~4 行，合计 ≤16 字，错落有致；
     - 标题管追问：≤20 字，按七型取材；封面与标题严禁同句复读；
  2. **正面网感三要素（有梗 · 贴近用户 · 追热点）**：
     - **要有梗**：融入当代发疯文学、流行黑话与幽默自嘲（精神离职、NPC觉醒、只要我没有道德、工位结界、水泥封心等），充当互联网嘴替；
     - **要贴近用户**：还原 20~30 岁职场女性真实生活微动作与物理实况（外卖备注、智能锁、工牌反扣、AA账单、泡脚桶等）；
     - **要追热点**：捕捉社会文化情绪与当下流行元素（反向整顿职场、断亲潮、短剧爽文风反转等）；
  3. **正文质感与真实呼吸感**：
     - **篇幅自由流动**：长短篇幅自然适配（微短自嘲、具体场景微动作、深度沉浸故事自如搭配），不设僵化字数枷锁；
     - **保护原声完整**：正文单行上限放宽至 ≤35 字，绝不机械断行切碎原声对话或金句引用；
     - **真实原声对话**：自然嵌入 1~2 句极短对话原话（如“大家都在就差你”、“你当老大的，多帮衬弟弟”）；
     - **真源金句与雷达对齐**：引用报告金句必须 100% 为真源字面子串，雷达维度与分值严格对应；
     - **聊完即停**：收在自然吐槽、行动转折或部落接头上，不升华、不喊口号；允许自然的疑问句、自嘲或召集收尾；
  4. **标签与元数据**：恰好 5 个标签（位1品牌词、位2品类词、位3真源结果名、位4场景词、位5情绪词）；每卡附带标准元数据行（包含 `cardId`、`切片`、`商品`）及置顶首评。
- **完成判据**：整批文案草拟完成，每张卡片封装在 ` ```text ` 块内，要素完整。

### Step 5: 双层源头机审自愈 (Red-to-Green Loop)
- **动作**：运行自检脚本并闭环修复：
  ```bash
  node ".agent/skills/xhs-note-operator/scripts/refine-notes.js" --file "design/product-docs/<测试名>/docs/YYYY-MM-DD_发帖文案.md"
  ```
  - **硬门禁（0 容忍）**：
    ① 0 词表（产品口吻词、15个临床医疗词、13个营销封杀词）；
    ② SSOT 真源核真（结果名、雷达维度与分值、金句原文完全吻合代码库）；
    ③ 版式与标签（封面 2~4 行 ≤16 字、标题 ≤20 字、标签恰好 5 个且前 3 位真源对齐）；
    ④ 批次去同构（原声对话不跨篇复用、开篇事件不跨篇复用、连续 3 篇骨架不同构）。
  - **网感建议看板（非阻塞参考）**：
    看板动态展示口语虚词覆盖度、热梗多样性、“合着”篇数、“测出”开头篇数等统计指标，作为写手润色参考，不作机械硬性阻断。
- **完成判据**：`refine-notes.js` 返回合格率 100%，红线违规为 0，批次去同构全绿。

### Step 6: 独立建档与交付 (Gate 2)
- **动作**：文案落盘至 `design/product-docs/<测试名>/docs/YYYY-MM-DD_发帖文案.md`；向大哥汇报资产清单与自检看板，等待下一步指令。
- **完成判据**：文件成功落盘并通过机审，获得大哥明确验收确认。
