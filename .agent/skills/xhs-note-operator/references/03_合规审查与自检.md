# 03 · 合规审查与自检（单一真实来源 SSOT）

> 本册为小红书发帖合规、红线词库、网感审查及自检清单的**全系统唯一真源**。
> 整合原 `xhs-note-copywriter` 的红线三分区与交付清单，以及 `xhs-note-analyzer` 的全域敏感词库与去爹味、去AI感审查法则。
> 别处只许引用，不许复述；自动化核验统一调用 `scripts/refine-notes.js`。

## 一、擦边红线三分区 (Controversy Zones)

**医疗为绝对红线，其余可适度试探。**

| 分区 | 内容 | 处理原则 |
|---|---|---|
| ✅ **放行** | 夸张、自嘲、阴阳、身份讽刺（如`免费保姆` / `我的善良没编制`） | 直接写，这是「野」和真人网感的主要来源 |
| ⚠️ **控比例** | 攻击性比喻，把父母 / 领导 / 亲戚设为靶子 | 可写，但同一测试批次内不超过三成 |
| ❌ **不碰** | 脏话、性暗示、身体羞辱、医疗词（`确诊` / `解药` / `抑郁` / `治疗` / `处方` / `症状` / `药物` / `疗效` / `挂号` / `心理疾病`） | 触发平台限流，且与情绪价值目标相悖 |

- 日常叙述词（`生病` / `体检` / `焦虑`）在非医疗主张语境下可用。
- **整活腔不豁免本表**：整活（自嘲玩梗 / 可转发幽默 / 阴阳式身份讽刺）只是表达姿态，**脏话 / 性暗示 / 身体羞辱 / 医疗词仍为 0**，且**笑点只许落在作者自己或荒谬的关系模式上**，不许拿用户或结果本人的痛处当笑点。
- **边界说明**：本表管的是小红书 feed 里的发帖文案与封面。千帆商图不直接受本表约束，但文案与商图必须严防医疗词串味。

## 二、四个 0 词表（出现任意一处 = 立即打回返工）

以下词汇在**封面、标题、正文、标签**中任意一处出现，即判不合格：

| 类别 | 零容忍词库 | 为什么（红线逻辑） |
|---|---|---|
| **产品口吻词** | `报告` / `第X页`（X 为数字） / `前半段` / `后半段` / `后半截` / `翻到最后` / `话术库` | 把「人话」变成冷冰冰的「产品话」，真人感当场断裂 |
| **测试术语** | `测出` / `测完` / `测了`（**全卡任意位置，含封面与标题**） | 暴露为营销测评产物，引发用户防御心理 |
| **本业务医疗词** | `确诊` / `解药` / `抑郁` / `治疗` / `处方` / `症状` / `药物` / `疗效` / `挂号` / `心理疾病` | 平台医疗风控绝对红线，无医疗资质必封号/限流 |
| **营销封杀词（9个）** | `敢不敢在评论区报个` / `说真的，你是不是也经常` / `不得不说，真的太准了` / `解析说` / `真的一针见血` / `赶紧去查查` / `快去测测看吧` / `低于60分` / `快去测测看` | 平台算法重点打击的机械营销套路与爹味话术 |

- **🔴 高危（删帖/限流）**：

## 四、爆款网感审查法则 (Anti-Ad & Anti-AI)

### 1. 逻辑闭环（严打标题党割裂，前 3 行必须接住封面 / 标题钩子）
- **钩子承诺什么，前 3 行必须兑现什么**：标题 / 封面承诺了什么具体事件、槽点或情绪冲突（如“终于离职了”、“拉黑了所有人”、“说好的暖冬去哪了”、“冻死我了 / 受够了”），正文**前 3 行必须立刻用具体生活动作、物理体感交代承接**（如提到了暖冬/冻死，前 3 行必须先写今天出门怎么冷、被风吹透、戴两层手套手依然冰凉等），不许空对空抒情。
- **严禁跳过钩子直接转进**：严禁封面/标题还在吐槽今天的寒潮，正文首行就直接跳到童年或回忆，造成钩子悬空割裂；先在今天接住钩子，再自然因果转折引出下文。
- 严禁标题制造巨大悬念，正文却全篇空洞议论或生硬推销测试。

### 2. 去爹味审查（第二人称转第一人称）
- **❌ 爹味说教体（严禁）**：“你是不是经常觉得下班很累？这叫情绪内耗，快来做个测试诊断一下！”（防御心理极高，像发传单）
- **✅ 第一人称日记体（推荐）**：“上个月我差点崩溃，下班连回微信的力气都没有，后来发现这叫低电量内耗...顺手把自测题放最后了，同款姐妹抱团取暖。”（真人叙事，分享姿态）

### 3. 【唠家常，不写作文】与人味硬门禁 (Casual Chat & Anti-AI)
- **唠家常，聊完就停**：正文是正常发帖唠家常，像跟人微信聊天，说到哪算哪，说完就停。**不许起承转合，不许首尾呼应，不许 callback**。
- **严禁为了凑结构硬加收尾（旧版强制微动作收尾作废，改为可选）**：反面例子——开头提了暖宝宝，结尾非要加一句“我把被子又往上拉了拉”来呼应——彻底删掉这种写法！微动作收尾仅在它是前面动作的自然延伸时才可用。
- **允许直接停在测试转折句本身**：例如停在“那里才适合我”，就完了，不用再收尾。**钩子口号只许在封面 / 标题，正文结尾绝对不许喊口号**。正文只能停在测试转折句本身，不许停在口号句上。正文不许出现“自己扛”、“破茧了往前走不回头”、“过好自己的日子比啥都强”等口号句。
- **同一个人、同一口气的吐槽**：封面、标题、正文必须是同一个人、同一口气的真实吐槽（例如标题“说好的暖冬呢，我手都冻僵了”，正文不许变回散文排比，不许列日程清单）。
- **正文后半段自然转到测试结果上**：例如“难怪我现在先顾自己”作为因果桥，顺畅停在行动转折“我先给自己买件厚的”，绝不再加口号收尾。
- **每行要有主语 / 时间 / 因果动作连贯（严禁碎片行）**：
  - 每行都要有主语 + 时间 + 动作或因果连贯，不许堆砌没有主语的形容词碎片；
  - **严禁天气报式单句与孤立碎片**：像“风也太凶了”、“我冻透了”、“冷死了”这种无动作、无因果的孤立天气感叹句一律禁止，必须换成带动作、有情境的因果句子（例如“我放学跑回家，手冻得握不住笔”）；
  - “算了吧”这种结果口头禅，没地方放就别硬放。
- **前 3 行生活情节与道具**：正文前 3 行必须包含日常生活实物或物理情节（暖宝宝、羽绒服、大骨汤、自提柜、工牌、工作机等），严禁通篇形而上的空洞议论。
- **口语虚词扰动（防风控与AI味）**：正文必须自然包含至少 2 个官方口语虚词（`其实`、`真的`、`反倒`、`索性`、`不过` 等，详见 `skill-data.js`），严禁全篇书面议论式说教。
- **短行断行破壁**：正文全文必须包含至少 2 处 ≤6 字的短行停顿，严禁全篇行长均匀对称（一堵墙）。

### 4. 双层机审分工架构
- **封面 / 标题层**：只查钩子强度、0 词表、字数规范（行数 2~4 行、短≤4、长≥6、总字数≤16；标题≤20字）。**强情绪破局口号仅限在封面与标题使用**（如“谁让我不痛快我就当场掀桌子……过好自己的日子，比啥都强”、“二十岁我悟出了一个硬道理。职场勾心斗角全当耳边风”、“不回应就是不失联。是把命还给自己”等高 CTR 钩子），**绝对严禁以“无生活场景道具”为由误判封面标题**！正文结尾严禁喊口号。
- **正文层**：查主语、时间、因果、前 3 行具体情节、口语虚词扰动、短行节奏与逻辑闭环。正文末行严禁口号升华，只能停在测试转折句本身。
- **元数据与标签真源核查**：机检强制核对 `result_name`（结果名）与品牌词、品类词，必须 100% 对齐 `测试画像.md` 与 `lib/*-data.ts`，绝不允许只数标签够 5 个就放过，绝不允许编造结果名。
- **历史回溯准则**：对历史笔记扫描时，分开上报【封面/标题不合格数】与【正文不合格数】。正文不合格系按最新人味新规回溯，只作记录，严禁批量改写或删除历史文件！

## 五、五条硬规格与排版标准 (Physical Specs)

> **规格 ≠ 配额**：规格是物理红线，不可妥协。自动化修整统一使用 `node "scripts/refine-notes.js" --file <path> --fix`。

1. **正文单行 ≤ 15 字**（硬规格，手机阅读不折行）：按意群智能回车断行；包含至少 2 处 ≤6 字短行停顿；
2. **封面 2~4 行，字数合计 ≤ 16**：多行时**须有一行 ≤ 4 字、一行 ≥ 6 字**；**3 行必须落成「长短长」或「短长短」**（`refine-notes.js` 机检），通过行长错落打破“一堵墙”视觉疲劳；
3. **标题一行、≤ 20 字**：一眼扫完，不挤满两行；
4. **标签恰好 5 个且真源对齐**：前 2 位（品牌词 / 品类词）全批字字相同且严格对照测试画像 `测试画像.md`（如城市测试品牌词为 `#城市人格`、品类词为 `#城市匹配测试`；大女主为 `#大女主觉醒`、`#原生家庭测试`），机检不许只数 5 个就放过；
5. **钩子原句 vs 末行字数**：末行若为分配表指定的互动钩子，**以钩子原句为准**（整句照抄，不许改写、不许砍成共用前缀）；无钩子时遵从目标末行字数。
6. **口语扰动度**：每篇正文命中 ≥2 种官方口语虚词（`ORAL_PERTURBATION_WORDS`）。

## 六、交付前自检清单 (Pre-Delivery Checklist)

### 6.1 两个固定项
- [ ] **红线词表写前过一遍**：动笔前扫视本册 §二 四个 0 词表与 §三 平替表。
- [ ] **换一双眼睛**：交付前由独立执行体或换位视角读一遍，只问一句：“哪一篇最假？”

### 6.2 逐卡看（一张一张过）
- [ ] **封面与标题互检**：遮住封面读标题猜不出封面（防复述）；遮住正文读封面一眼能认领（“这说的是我”）。
- [ ] **首行独立性**：封面、标题、正文首行三者并排，首行必须带来前两者都没有的细节、台词或动作，无字面复读。
- [ ] **正文单行字数**：每一行严格 ≤ 15 字。
- [ ] **封面行错落**：2~4 行，合计 ≤ 16 字；有一行 ≤4 字、一行 ≥6 字；**3 行须为长短长或短长短**（对照分配表「封面节奏」列）。
- [ ] **标题长度**：加权长度 ≤ 20 字，无冗余括号与伪补刀。
- [ ] **0 词表清零**：封面/标题/正文/标签无产品词、无测试术语、无 10 个医疗词、无营销封杀词。
- [ ] **去爹味与【唠家常】**：第一人称聊天叙述，同一个人同一口气吐槽，无假大空宣誓升华（口号只在封面/标题，正文结尾严禁喊口号），说到哪算哪聊完即停（微动作收尾为可选，严禁硬凑首尾呼应 callback）。
- [ ] **钩子兑现与逻辑闭环**：正文前 3 行必须接住封面/标题钩子（提了寒潮/降温/暖冬前 3 行必有今天冷、风吹透、手凉的生活情节与动作），不许空对空，不许开头直接跳到童年回忆。
- [ ] **严禁碎片行**：每行都有主语 + 时间 + 动作或因果连贯，绝无孤立天气报单句（如“风也太凶了”、“我冻透了”）或无主语碎句。
- [ ] **结果名与品牌标签核真**：对照 `docs/测试画像.md` 常量表核对 `result_name`（绝不许编造结果名）与位1品牌词（如城市为 `#城市人格`，绝不许错写为 `#性格城市匹配`），机检严禁只数 5 个就放过。
- [ ] **低气压档禁调笑**：脆弱认领档位严禁使用自嘲与梗化表达；低气压档零 emoji。
- [ ] **模式一数字量纲**：模式一封面必须带阿拉伯数字或百分比生活量纲（如 `90%`、`3天`），严禁考试得分词（如 `低于60分`）。
- [ ] **口语虚词与扰动**：正文自然包含至少 2 个官方口语虚词（`其实`、`真的`、`反倒`、`索性` 等），破除 AI 规整感。
- [ ] **短行节奏停顿**：正文包含至少 2 处 ≤6 字短行停顿，行长起伏错落，非一堵墙。

### 6.3 整批看（全批摊开）
- [ ] **首行模具检查**：所有正文首行抽出来排成一列，没有句式撞车。
- [ ] **标题与封面多样性**：标题无孪生句，封面行数与视觉节奏错落不一。
- [ ] **收尾手势差异**：每篇收束各不相同，聊完即停或自然停在测试结果转折句，杜绝硬加结构。
- [ ] **四档均衡覆盖**：选定测试的四种情绪档位均有对应卡片覆盖。

## 七、自动化审查与自检脚本

在文档初稿生成完毕后，一键执行双层自动化核验与修复：

```bash
node ".agent/skills/xhs-note-operator/scripts/refine-notes.js" --file "design/product-docs/<测试名>/docs/YYYY-MM-DD_发帖文案.md" [--fix]
```

- **双层机审**：
  - 封面/标题层：自动扫描 0 词表、字数规范（行数、长短节奏、标题长度）；放行高点击强情绪口号钩子，严禁用正文实物规则误杀；
  - 正文层：自动智能断行正文使其严格 ≤ 15 字，核验口语虚词扰动、短行停顿、前 3 行生活情节与实物、逻辑闭环承接、拦截说教句与假大空口号；
- **自检报告分离**：分开上报封面/标题不合格数与正文不合格数；
- **历史回溯特别说明**：历史旧文回溯不合格仅反映新门禁标准的历史体检，绝不代表全盘报废，严禁依据扫描结果批量改写或删除历史文件；
- **--fix 定向自愈规范**：只执行确定性机械修复（断行、修标题、剥离末行宣誓口号、第二人称转第一人称、补齐固定品牌/品类标签）；通篇空洞无实物卡片打上 `[REWRITE_REQUIRED]`，严禁胡编乱填。
