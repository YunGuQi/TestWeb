## 零、六个词（贯穿全篇的心智锚）

写作与自检时，**用这六个词思考，不要展开成长句**：

| 词 | 含义 | 判据 |
|---|---|---|
| **口音** | 这条是谁在说话。先定说话人，再落笔 | 能一句话说出「这是个什么脾气的人」 |
| **档** | 情绪档位：破防 / 解气 / 冷笑 / 认命 | 同一结果的四篇应尽量不同档 |
| **缺口** | 内容自带的悬置，制造蔡加尼克开口 | 说了前菜，把主菜留在**读者心里**。不引报告、不提页数 |
| **野** | 允许的不完美 | **宁可 5% 野，不要 0% 齐**。真人发帖是参差的 |
| **指纹** | 同质化留下的可检测残留 | 同测试内任意两篇不得有逐字相同的行 |
| **双位** | 封面管**认领**，标题管**追问** | 标题读完只剩「跟封面一样」= 标题位白送 |

> **底线不变**：自检清单全过（字数 / 行宽 / 敏感词）是及格线，不是满分线。**及格线之上拼的是「口音」和「野」。**

## 零.5、测试画像（每测试一份，开工先读）

本 SOP 的**骨架通用**（双位 / 三层 / 取材七型 / 展开五型 / 折叠线），**肉是专用的**——口音、情绪档、标签品牌词、可用字段，每个测试都不一样。

**画像落在每个测试自己的目录下**：`design/product-docs/<测试名>/docs/测试画像.md`。**开工第一件事就是读它，读完才能动笔。**

**画像里有三项是按「每测试一次」的频率预计算的常量**——**口音表 / 评论区首条 / 红线清单**。这三项对同一个测试恒定不变：脾气底色不因换一批结果而变，承接话术不因换一批结果而变，要避开的词更不会变。所以它们**写一次存进画像，之后每次开工直接读**，不再现场推导——推导既慢，又会漂移。定义见 §零.5.1~§零.5.4。

**没有画像文件的测试**，先按下面这张空表新填一份（三区块一并建），落盘到同一位置：

| 项 | 值 |
|---|---|
| 测试目录 | `design/product-docs/<测试名>/` |
| 数据源文件 | `lib/<该测试>-data.ts` |
| 结果数 | ? |
| **#位1 品牌词**（全批恒定） | ? |
| **#位2 品类词**（全批恒定） | ? |
| **情绪四档** | ? / ? / ? / ? |
| **口音基调** | ? |
| **独有素材字段** | ? / ? / ? / ? / ? |
| **口音表**（常量，见 §零.5.1） | 全量结果逐条「这是个什么脾气的人」+「允许整活 ✓/✗」 |
| **评论区首条**（常量，见 §零.5.2） | 可直接复制的成稿 |
| **红线清单**（常量，见 §零.5.3） | 三分区摘录 + 本测试专属弃用词及替代表述 |

**填表三条纪律**：

1. **四档必须从该测试自己的情绪光谱里取**——`破防 / 解气 / 冷笑 / 认命` 是创伤测试的四档，**不是通用四档**。恋爱测试套它会写出一堆该甜的文案在哭，城市测试套它会认错命；
2. **#位1 / #位2 全批恒定**，测什么写什么，不许借用别的测试的品牌词；
3. **独有素材字段照抄 `lib/*-data.ts` 的真实字段名**，不得凭印象写。

> **口径**：本 SOP 正文凡出现 `triggers` / `antidoteList` / `radar` / `quote` / `content`，一律读作「该测试对应位置的**真实字段**」。字段名是该测试的，不是 SOP 的。

> **SOP 与画像的分工**：**SOP 说怎么写，画像说这个测试的肉是什么。** 画像里没有的，回代码库取；代码库里没有的，不许编。

### 零.5.1 口音表（常量 · 每测试写一次）

**是什么**：该测试**全量结果**逐条一句「**这是个什么脾气的人**」。它是「口音基调」的下沉——**基调管整个测试的底色，口音表管每个结果各是什么脾气**。

**填写口径**：

1. **必须覆盖全量结果**——该测试有几个结果就写几条，**不因本次走 A / B / C 哪条路线而缺项**。口音表是常量，路线是变量；表按全量写，路线随便换；
2. **数结果数不许用 `^\s+id:\s*['"]` 这类正则**——它会把题目 id、选项 id 一起数进去（实测把某测试的 6 个结果数成 27）。要数 `results` 数组的元素本身，或看每个结果对象的 `title` / `key` 字段。**数错了这张表就废了**；
3. **一条一句话**，句式是「这是个什么脾气的人」，**不是形容词堆砌**——❌「敏感、倔强、清醒」；✅「把委屈咽下去、再轻描淡写说出来的人」；
4. **必须从底层结果定义萃取**（结果描述 / 金句 / 标签）——**不读历史发帖文案**（该铁律只在 `SKILL.md` 声明一次）；
5. **不得与「口音基调」冲突**：口音表是基调在该结果上的具体化，不是另起一套脾气；
6. **第三列「允许整活」是常量，两态取值 ✓ / ✗**——定义、作用域与档位归属见 §2.4.1。判定依据是**该结果的脾气经不经得起玩梗**（松弛 / 锋利 / 自嘲底色 = ✓；易碎 / 沉 = ✗），**不是**「本次准备把它写成哪一档」；
7. **每个测试至少要有若干条 ✓**——可整活档（§2.4.1 归属表）的整活卡只能从 ✓ 的结果里出；全批都填 ✗，等于这两个档整批放弃了「好笑、想转发」这层分享动机（自检清单 §7.4「有没有一张你会想转发的」就会落空）。

**格式**：

| 结果名 | 这是个什么脾气的人 | 允许整活 |
|---|---|---|
| `<结果名 1>` | ? | ✓ / ✗ |
| `<结果名 2>` | ? | ✓ / ✗ |

### 零.5.2 评论区首条（常量 · 每测试写一次）

**是什么**：笔记发布后作者发表并置顶的**首条引导评论的完整成稿**（04_分发与排期.md §五 第二道齿轮）。**这是唯一的显式转化通道，同一测试的全部卡片共用这一条。**

**填写口径**：

1. **写成可直接复制的成稿**——不留 `?`、不留待填占位、不写「参考 04_分发与排期.md」这类指针。画像里放的就得是能直接粘贴的那句话；
2. **必须含主页店铺承接**（「在主页店铺自取同款…」）——这是转化通道本体，漏掉它等于整批文案没有转化通道；
3. **正文零产品词**（词表见 03_合规审查与自检.md §7.2「产品口吻词」）；
4. **两个模板二选一**：
   - **痛点型**（结果是「人 / 人格 / 关系」的测试）——参考形态：「拿到完整结果和防吸血指南的姐妹，在主页店铺自取同款测试，别再当免费工具人了🥺」
   - **城市型**（结果是「地点 / 城市」的测试）——**须同时含相克城市与高能充电日程双钩子**，参考形态：「测出自己的相克城市和高能充电日程的，在主页店铺自取同款车票，千万别去八字不合的地方受罪[握手]」
5. **emoji / 方括号表情按原样保留**——它就是这条评论的实际形态（这条评论不在卡片内，其 emoji 规则见 03_合规审查与自检.md §7.3 末的「emoji 的作用域」注解）。

### 零.5.3 红线清单（常量 · 每测试写一次）

**是什么**：03_合规审查与自检.md §四 擦边红线三分区的**本测试摘录** + 本测试**专属弃用词**（逐条配文案侧替代表述）。

**填写口径**：

1. **分区摘录**：按 ✅ 放行 / ⚠️ 控比例 / ❌ 不碰 三档，各摘本测试适用的条目，每条配一个**本测试的**例子。❌ 档的医疗词是绝对红线，逐条列出；
2. **专属弃用词的来源**：扫该测试 `lib/*-data.ts` 的**原始字段值**（结果描述 / 标签 / 金句），凡命中医疗类或与情绪价值目标相悖的表述，**逐条列出**，并给出**文案侧替代表述**——优先改用同结果 `tags` 里的真实词，**不要自造新词**；
3. **不许抽样**：术语密度高的测试（如深度情绪内耗）**须穷尽**。漏一条就等于这条会在某一批文案里被写出去；
4. **固化成文字，不依赖记忆**——凡「我记得这个不能用」的，都必须落到本清单。靠记忆的红线必漏。

**格式**：

| 弃用表述（源数据原文） | 出处字段 | 文案侧替代表述 |
|---|---|---|
| ? | ? | ? |

### 零.5.4 读取逻辑：两态判定（硬约束）

**开工读画像时，先判定三区块是否存在：**

| 态 | 判据 | 动作 |
|---|---|---|
| **缺** | 画像里没有 口音表 / 评论区首条 / 红线清单（任一或全部缺失） | 按 §零.5.1~§零.5.3 的定义**补齐后落盘**，再进入写作 |
| **有** | 三区块齐备 | **直接读用，不得重新推导** |

**「不得重新推导」是硬约束**：画像里已有口音表，就不许再为每个结果现写一句口音；已有评论区首条，就不许再重写承接话术。重写的代价不只是慢——**它会产出与上一批不一致的版本，让同一个测试的口音人格分裂**，用户能感觉到不是同一个人在说话。

**空白画像（新测试上线）**：三区块一并按定义建档，**落盘之后再动笔**。没建档就动笔 = 本次产出的口音与红线无据可依。

**三区块按「每测试一次」的频率维护**：只有该测试的结果定义本身变了，才回画像改这三区块。

### 2.4 情绪四档（每测试自定义）

**四档不是通用的**——`破防 / 解气 / 冷笑 / 认命` 是**大女主觉醒这一类的创伤光谱**。恋爱测试套它会哭错场，城市测试套它会认错命。

**四档从本测试的情绪光谱里取——先读该测试的 `测试画像.md` 再动笔。** 定档三条纪律：

1. 四档必须是**四种不同的情绪**，不是同一情绪的四档强度；
2. 四档必须**都能让读者认领**——取不出认领感的档，是文案的档，不是用户的档；
3. 同一结果的四篇**尽量分属不同档**，避免一档激动到底。

**四档语感示例见该测试的 `测试画像.md`**（如大女主：破防 / 解气 / 冷笑 / 认命）。

### 2.4.1 整活轴（与情绪四档正交的第二条轴）

**是什么**：整活 = **自嘲式玩梗 / 可转发幽默 / 阴阳式身份讽刺**。它补的是「好笑、想转发」这一层分享动机——情绪四档回答「这条有多痛 / 多爽」，整活回答「这条能不能让人笑一下、顺手转给朋友」。

**为什么是第二条轴、不是第五档**：档管**情绪温度**，整活管**表达姿态**。同一档位可以有两版（同一篇「解气」，可写成正经宣告，也可写成自嘲玩梗）。加一条轴不破坏情绪模型；新增档位会把模型压扁。

**作用域按档位切，两态**：

| 态 | 判据（按情绪温度，不按档名字面） | 大女主觉醒（创伤光谱 · 原型） |
|---|---|---|
| **可整活** | 情绪上扬 / 带攻击性 / 自带自嘲 | 解气 / 冷笑 |
| **低气压**（不整活） | 脆弱易碎；或郑重认领；或下沉躺平 | 破防 / 认命 |

**低气压档为什么不玩梗**：这些档里用户正处在最脆弱、最需要被接住的时刻——玩笑会被读成嘲讽；「算了」的底色被玩梗一冲就变成轻佻。

**各测试的档位归属是常量，登记在此表**（新测试上线时补一行；**判定看情绪温度，不看档名字面**）：

| 测试 | 可整活档 | 低气压档 |
|---|---|---|
| 大女主觉醒测试 | 解气 / 冷笑 | 破防 / 认命 |
| 命定恋人 | 嘴硬 / 嘲甜 | 心动 / 认栽 |
| 性格城市匹配 | 自嘲 / 反骨 | 认领 / 向往 |
| 恋爱物种领养中心 | 炸毛 / 自嘲 | 撒娇 / 破防 |
| 深度情绪内耗 | 自嘲 / 解气 | 摆烂 / 认领 |

> **这张表是档位归属的唯一真源**：emoji 规则与整活卡配额**不硬编码「破防/认命、冷笑/解气」**——那样只对大女主成立，另外 4 个测试的档名对不上，规则会**静默空转**（不误报、也不约束）。现在两条都按本表的**两态**判：`.agent/skills/xhs-note-operator/scripts/skill-data.js` 的 `MOOD_TABLE` 是同名执行副本，供两个生成器读取。
> **改表要动两处**：改完本表，必须同步 `skill-data.js` 的 `MOOD_TABLE`（测试名或档名任一侧多一个少一个，生成器会当场报错停下；同一档名同时落在两态同样报错）。
> **新测试上线**：两处各补一行。**档名不在本表里的卡**按自检清单 §7.3 的 emoji 条与低气压条判不了档，会当场暴露缺登记——这是刻意设计的，不是噪声。

**三条纪律**：

1. **整活不是红线豁免**——整活腔仍受 [`03_合规审查与自检.md`](03_合规审查与自检.md) §四 三分区约束（脏话 / 性暗示 / 身体羞辱 / 医疗词 = 0），且**笑点只许落在作者自己或荒谬的关系模式上**，不许拿用户或结果本人的痛处当笑点；
2. **标注语法**：整活卡在卡片标注行追加 `｜整活=✓`，非整活卡不写；交付前自检清单 §7.3 的低气压条与 §7.4 的转发条按此判定（口径见 [`03_合规审查与自检.md`](03_合规审查与自检.md) §7.3）；
3. **每个结果能不能整活，查画像口音表第三列**（§零.5.1），不现场拍脑袋；每个测试至少留若干条 ✓（§零.5.1 口径 7）。

**反面（这样不算整活）**：加个 emoji、加个感叹号、末行加「哈哈哈」。整活是**结构**——自嘲的对象、荒谬的对照、阴阳的落点，三样缺一样就只剩油腻。

## 六、主推结果日例建档流水线（步序与 [`SKILL.md`](../SKILL.md) §六 **同步**）

**本表只列步序与那一步吃的产物 / 用的生成器**，每步的口径在 [`SKILL.md`](../SKILL.md) §六——**两处步数必须相等**（现为 **11 步**）。改一处，另一处当场跟着改；步号对不上时，以 `SKILL.md` 为准并立即回填本表。

| 步 | 做什么 | 产物 / 生成器 |
|---|---|---|
| 1 | 读**测试画像**（品牌词 / 四档 / 口音基调 / 可用字段 + 口音表 / 评论区首条 / 红线清单三区块） | 该测试 `docs/测试画像.md`；三区块定义见本册 §零.5 |
| 2 | **问用户**走 A / B / C（没答复不许动笔） | [`SKILL.md`](../SKILL.md) §6.1 |
| 3 | **生成工作包**：素材 / 红线 / 自检清单 / 骨架压成一个文件 | `scripts/make-workpack.js` → `.scratch/<slug>/workpack.md` |
| 4 | **生成分配表**：跨卡配额一次排死 | `scripts/make-plan.js` → `.scratch/<slug>/plan.md` |
| 5 | **读口音表**（查表，不查脑子） | 工作包 §2；未覆盖时回本册 §零.5.1 并整表补齐落盘 |
| 6 | **全量构建**：照分配表取型，逐篇落三层 + 写正文 + 写标注行 | 工作包 §5 + 分配表 |
| 7 | **长尾降级**（仅 A / B；C 整步跳过） | 只换 `title` / `quote` / `tags`，只作结果页兜底 |
| 8 | **独立建档** | `design/product-docs/<测试名>/docs/YYYY-MM-DD_发帖文案.md` |
| 9 | **交付前自检**：逐条过清单（含两个固定项），再调 `refine-notes.js` **整批一次审**；并行分片时各片过「逐卡看」，**合并后主代理把「整批看」过完** | 工作包 §4；清单全文见 [`03_合规审查与自检.md`](03_合规审查与自检.md) §七（口径见 [`SKILL.md`](../SKILL.md)「执行模式」小节） |
| 10 | **排期与分发** | [`04_分发与排期.md`](04_分发与排期.md) §六 |
| 11 | **触发 GATE 暂停**：汇报资产清单 / 篇数 / 清单逐条结论 / 发布日历 | 停机等指示 |

> **第 3、4 步为什么在动笔前**：这两步把「整批写完才算得出来」的东西提前到开写前——工作包把 7 份文档的串行阅读压成 1 份；
> 分配表把跨卡配额（模式 / 取材型 / 起手型 / 展开型 / 档 / 缺口型 / 整活 / emoji / 封面行数 / 末行字数 / 钩子 / 钩子形态）一次排死。
> 留在写完之后才发现，代价就是整批返工。
> 两份产物都是**中间件**，一律落 `.scratch/<slug>/`，**不进** `design/product-docs/`（那里只放最终发帖稿）。
