## CRITICAL: Single HTML Safety Guidelines (单页面技术防坑铁律)

由于单页面无法依赖现代框架的诸多机制，在开发时必须绝对注意以下几点：

1. **原生截图渲染机制的坑**：
   - **绝对禁止**使用 `html2canvas`，移动端兼容性极差。**必须**使用 `html-to-image.min.js` 进行渲染。
   - 目标截图元素外层必须包裹一层带有 Padding 的 `#capture-wrapper`，否则发光特效或边缘印章必定会被系统粗暴裁断。

2. **移动端保存风控拦截**：
   - **绝对禁止**在生成图片后直接调用 `link.download`。微信及小红书内置 WebView 会严厉拦截此类隐式下载行为。
   - 必须将生成的 Base64 图片数据赋值给一个全屏模态框内的 `<img>` 标签，并加上极为显眼的文案：“✨ **长按图片保存到手机** ✨”。

3. **绝对定位的无底洞**：
   - 在处理类似右上角印章这类 `position: absolute` 的组件时，CSS 规则中**切忌同时使用 `top` 和 `bottom`**。否则该元素在某些特定 iOS WebView 中将被计算为 100% 高度而造成无限垂直拉伸。

4. **防误触后退机制（最容易导致崩溃的点）**：
   - 用户极易手滑点击“左滑返回”。你必须强制写入 Hash 虚拟路由拦截代码或 `pushState`。
   - **极度注意**：在 `renderResult()` 渲染结果页面时，**必须强制写入一次 `location.hash = '#result'`**。如果忘写，浏览器会停留在 `#quiz`，当用户点开并关闭底部的其它弹窗触发 `history.back()` 时，会引发 `popstate` 误判，直接导致用户被一脚踢回首页，致使答题数据全盘灰飞烟灭！
