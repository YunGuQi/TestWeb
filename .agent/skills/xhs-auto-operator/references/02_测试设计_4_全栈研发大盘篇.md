# 02_测试设计_4 - 全栈研发大盘工作流 (Full-Stack Platform SOP)

针对小红书测试平台，目前项目以 **全栈融入框架大盘 (test-platform)** 为核心主推研发模式。
无需搭建新项目，所有新增测试均作为一个功能路由，直接接入现有的 Next.js 大盘系统。

---

## 1. Architecture Consensus (一次开发，多端部署)

大盘采用“全栈前后端融合”架构。在部署上，为实现“写一套代码，同时在 Vercel (海外节点) 与 宝塔面板 (国内稳定节点) 运行”的需求，做出以下终极决策：
- **数据库大一统**：无论是 Vercel 的 Serverless 环境，还是宝塔 Node 守护进程，**统一连接部署在公网宝塔服务器上的同一个 PostgreSQL/MySQL 数据库中心**。
- **数据互通**：实现多端部署后的数据 100% 互通，运营在 `/ops-dashboard` 后台可管理来自两端入口的所有测试订单与流水。

## 2. Execution Steps (研发 SOP 标准五步法)

在拿到《策划与方案篇》的输出后，严格执行以下步骤将新测试融入大盘：

### Step 1: Create Routes & Views (创建测试前端路由与视图)
- 在 `design/test-platform/app/<新测试标识>/` 创建页面主入口。
- 构建四个核心状态组件：`LandingView`, `QuizView`, `ResultView`, `HistoryDrawer`。
- **注意**：界面样式与排版必须严格执行 [02_测试设计_3_通用UI与排版规范.md](02_测试设计_3_通用UI与排版规范.md) 的要求，如瀑布流结果页、30%诱饵vs70%订单验证遮罩、常驻印章、微小的防同质化数值波动等。

### Step 2: Database Injection & Local Fallback (数据库植入与本地常量兜底)
- **库表复用**：绝不可随意建新表，所有新增业务复用 `prisma/schema.prisma` 中的统一实体表，并通过 `testId` 作为租户隔离键。
- **双线高可用 (🚨 核心铁律)**：
  每个测评项目必须准备两套数据流：
  1. **DB-First**：通过 `seed.ts` 或临时脚本，将题库和结果配置压入大盘云端数据库。
  2. **Local Fallback**：将题库提取为独立的本地常量文件（如 `lib/<testId>-data.ts`），当查询后端接口遇到断网、超时、DB为空时，接口自动向本地常数题库降级兜底算分，确保任何情况下用户不会白屏报错。

### Step 3: Connect Backend & Security APIs (对接后端算分与安全接口)
1. **题库加载**：前端请求 `/api/questions?testId=<新测试标识>`，后端务必过滤掉权重 `scores`，只下发题干与选项文本。
2. **提交测算 (`/api/submit`)**：
   - 携带 `{ deviceId, testId, answers }` POST 提交。
   - 算分后生成结果 ID 写回 `TestRecord`。
3. **安全与订单验证 (`/api/verify`)**：
   - 在前端结果页渲染时，必须先弹出拦截，用户输入验证码调用该接口放行后，方可展现最终结果。
   - 🚨 **避坑预警 (极易出错)**：在前端请求 `/api/verify` 时，JSON payload 中必须显式传入 `testId: '<新测试标识>'`。如果不传，后端将默认按历史测试去查询数据库，导致当前测试的卡密永远报错“激活码无效”。
   - 🚨 **雷达图数据格式预警**：检查本地题库 (如 `lib/<testId>-data.ts`) 导出的雷达图 `radar` 数据结构是否与 `ResultView.tsx` 中图表组件要求的结构匹配，切忌盲目拷贝旧代码导致 `.map is not a function` 白屏崩溃。

### Step 4: Register Ops Dashboard (注册大盘运营后台)
- **后台导航菜单**：务必在 `app/ops-dashboard/AdminNav.tsx` 的 `TESTS` 数组中添加该测试的配置，否则运营管理员在左侧边栏无法切换到新项目。
- **卡密前缀防串号**：务必在 `app/api/admin/generate/route.ts` 中为该测试配置专属的卡密前缀（如 `CITY-` 或 `LOVE-`）。**禁止使用混用的默认前缀**，以免不同项目的验证码互相盗用。

### Step 5: Deployment & DLP Bypass (特权脱壳部署与发布)
- 详细的双端部署架构、宝塔 MySQL 与环境变量配置，详阅 [03_部署与运维篇.md](03_部署与运维篇.md)。
- 若在 Windows 本地打包上传至 Linux 运行遭遇 Turbopack 哈希别名 Bug 或 Zod 崩溃，严格依照 [04_跨平台构建与部署避坑指南.md](04_跨平台构建与部署避坑指南.md) 修复。
- 由于开发机透明加密设备 (TSD/DLP) 会加密 `.css` 和静态产物，禁止使用普通压缩，必须严格遵循 [05_防泄密与安全脱壳规范.md](05_防泄密与安全脱壳规范.md) 执行一键聚合打包：
  ```bash
  npm run pack
  ```
  该命令已将以下标准工序流水线化：
  1. `node generate-inline-css.js`（提取解密 CSS 并转为 TS 常量防加密）；
  2. `next build --webpack`（强制使用 Webpack 编译器生成生产包）；
  3. `node pack_dlp.js`（Node 进程白名单特权内存脱壳，排除本地 SQLite 库，生成纯明文 `deploy.zip`）。
- **宝塔部署 (🚨 核心铁律)**：上传 `deploy.zip` 后，**必须先删除原有的 `.next` 目录再解压**，绝不能直接覆盖（否则旧加密文件残留）。最后在 Node 项目管理器或 PM2 中重启服务。

## 3. Troubleshooting & Safety Guidelines (防坑指南)
- **🚨 CRITICAL RED LINE (致命红线预警)**：绝对禁止在开发新测试时私自升级或更改 `package.json` 中的底层依赖版本（尤其是 `Tailwind CSS` 与 `Next.js`），这会导致线上全站白屏与排版崩塌！绝对禁止修改 `schema.prisma` 的表结构。
- **服务端渲染 (SSR) 兼容性**：Next.js 调用截图工具（如 `html-to-image`）如果在服务端会报错，相关保存长图的组件必须通过 `use client` 强制在客户端渲染。
- **接口防刷拦截**：提交测试和订单校验接口需具备 IP 频控（Rate Limiting），防止恶意撞库或白嫖行为。
- **离开防流失**：答题中断时（如误触回退浏览器），必须在前端弹窗确认“确定离开吗？进度将不被保存”，防止流量无效损失。
