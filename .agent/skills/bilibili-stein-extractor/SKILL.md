# B站互动视频分支逻辑提取

## 核心认知（先读）

- **分支逻辑不在视频文件里**。用户下载的 mp4 只是各段素材，跳转关系、数值变量、判定条件都存在B站服务端，必须凭 BV 号在线拉取。
- 整条链路只需 3 个匿名 GET 接口：`view`（拿 cid）→ `player/v2`（拿 graph_version）→ `edgeinfo_v2`（逐节点遍历）。字段细节见 [references/api_reference.md](references/api_reference.md)。
- **B站会为每条路径复制节点**（同一道题在图里出现多次），必须按"选项内容+动作+条件"去重，否则 6 道题会看成 34 个节点。
- **结果视频的真实 cid 在指向结果的边上（choice.cid）**，叶子节点的 story_list 不可靠（常回填入坑口 cid）。
- 题干口播、结果解析文案在视频画面里，接口**拿不到文字**——提取完毕后提示用户按 cid 对照视频分段转写。

## 快速开始

```bash
python3 scripts/extract_stein.py <BV号或视频URL> [-o 输出目录] [--cookie "SESSDATA=..."] [--delay 0.3]
```

脚本自动完成：校验是否互动视频 → 取 graph_version → BFS 遍历全图 → 去重题目 → 解析计分动作与判定条件 → 统计各结果路径数。

输出两个文件（文件名取自视频标题）：

- `*_graph.json` — 完整分支图原始结构（节点、选项、条件、数值动作、隐藏变量）
- `*_quiz.json` — 推断出的问卷结构（去重后的题目、每选项的分值/变量、结果区间、结果视频 cid）

终端摘要直接给出：去重后题目清单（含每选项加到哪个变量几分）、结果判定区间、结果视频 cid、路径总数。

## 输出解读要点

- `native_action` 形如 `$var=$var+2.00`，即"选此项则变量+2"；脚本已解析为 `var/delta`。
- 结果判定边（通常在"查看结果"节点上）的 `condition` 形如 `$var>=5.00 && $var<=10.00`，脚本已解析为 `min/max` 区间。
- 选项文本为全角括号且无动作的（如（查看更多选项）（返回上层））标记为 `is_nav`——是导航不是作答项；合并多层选项页时把导航项两侧的真实选项拍平。
- 摘要中的"路径数"是图路径数，**含导航边与回边，通常大于真实作答组合数**；要精确组合数，取去重后的计分题用选项分值做笛卡尔积穷举。
- `hidden_vars` 里 `type=2` 是随机值变量；未被任何动作/条件引用的变量是作者留下的废案，忽略。

## 常见失败与对策

- **-412 风控**：加大 `--delay`（如 1.0），或 `--cookie` 传入浏览器登录后的 `SESSDATA`。
- **提示"剧情图被修改已失效"**：graph_version 过期，重新走一遍 player/v2 取最新值。
- **需要登录才能看全部结局**：匿名拿到的图可能不完整，带 SESSDATA 重跑对比节点数。
- **非互动视频**：`view` 接口无 `stein_guide_cid`，脚本会直接退出并说明。

## 版权边界

提取逻辑结构（几分对应什么结果）本身不受著作权保护，但题目文案、结果解析文案属于原作者。若用户目的是搬运/二次发布，提醒其取得授权或自行改写文案。

## 业务归档规范（自动落盘）

- **强制落盘路径**：提取并拆解完题目、答案、权重、结果判定与心理分析后，必须自动整理为标准 Markdown 文档，写入：
  `design/product-docs/<测试名称>/docs/product_plan.md`
- **文档必备要素**：
  1. 核心定位与产品包装（主题、隐喻、分享噱头）
  2. 底层算法架构（单轴积分或多维雷达、各维度含义与判定优先级）
  3. 题库设计（题干、选项、加分权重、定性标签）
  4. 结果判定与深度心理学分析（全结局区间、人格属性、依恋类型、雷达关键词、长文本解析）
  5. 资产与物料流转指引（B站原源、本地视频切片路径、商品卡密前缀）
