# PRD: 移动端手机视口适配与文本排版防折行加固规范

## Problem Statement

当前 `test-platform` 平台承载的 5 大心理测试（`city` 城市性格测试、`emo` 情绪消费账单测试、`destiny-lover` 命定恋人测试、`family-origin` 原生家庭图谱测试、`love-species` 恋爱物种特工测试）在小红书 App 与微信内置浏览器（移动端典型视口 375px/390px）中，存在局部文本挤压、长标题被不合理拆断换行、按钮文字折行以及胶囊标签字符内断裂的问题。
特别是 `city` 测试，其未解锁状态下的封存遮罩卡片（OrderOverlay）中标题最后 3 个字“已封存”被挤压独立换行，黑色解锁主按钮“【列车长验票】立即检票解锁 ➔”因宽度限制折成上下两行；且车票顶部受右上角防伪钢印影响，不合理添加了全局右内边距，导致长标题与避难所地名在窄屏下被迫换行堆叠。这直接损害了视觉高级感，破坏了小红书受众的沉浸式测试与付费转化体验。

## Solution

遵循 `impeccable` 的 adapt 响应式与排版规范，针对 5 大测试的移动端显示进行外科手术式无损加固：
1. **重构 `city/OrderOverlay.tsx` 封存卡片**：
   - 优化标题文案并自适应字号与间距，确保单行优雅居中；
   - 优化解锁按钮容器尺寸与内边距，挂载 `whitespace-nowrap`，彻底根除按钮文字折成两行的顽疾；
2. **重塑 `city/ResultView.tsx` 顶部安全区**：
   - 清除无必要的全局 `pr-20` 挤压，释放横向排版空间；
   - 为城市标签 tags、副标题及高光 Badge 增加 `whitespace-nowrap`，杜绝单字被折裂；
3. **5 大测试全局移动端防折行护栏**：
   - 全面审查并强化 `emo`、`destiny-lover`、`family-origin`、`love-species` 的标签胶囊、关键数值卡片、高光勋章与关键行动号召按钮，赋予 `whitespace-nowrap` 防线；
   - 确保在 360px ~ 430px 全主流手机视口下文字零错乱、零不合理换行、零横向溢出滚动条。

## User Stories

1. As a 手机端受测用户，我希望在进入城市测试结果页未解锁状态时，看到清晰、工整、单行排列的“专属车票深度避难指南已封存”卡片与解锁按钮，以便感受严谨高级的界面质感，顺畅点击核销。
2. As a 测出长地名（如“阿勒泰·禾木夏牧场”）的用户，我希望在车票顶部看到完整连贯的避难所取景地标与城市称号，而不是被截断或挤压折行。
3. As a 任何测试的受测者，我希望所有结果标签（tags）、百分位 Badge 和按钮文本都完整自洽，不会在词语中间发生突兀折行。
4. As a 移动端（尤其是 360px~375px 小屏）用户，我希望页面一拉到底自然流畅，没有任何水平晃动或横向溢出滚动条。

## Implementation Decisions

- **组件样式微调优先**：优先利用 Tailwind CSS 的响应式原子类与 `whitespace-nowrap` / `shrink-0` 进行微调，不破坏既有设计语言与主题变量。
- **文案精算与排版自洽**：针对卡片标题与按钮文字，微调字数（如 14-16 字）与 letter-spacing，避免死板指定过大固定宽度。
- **跨平台一致性保障**：桌面端（PC）与移动端共享同一 DOM 结构，利用响应式断点（sm: / md:）平滑适配。
- **零破坏性原则**：严禁修改既有业务逻辑、API 数据接口以及卡密核销链路。

## Testing Decisions

- **视口测试矩阵**：在 Chromium 移动端视口（375x812 iPhone SE/Mini、390x844 iPhone 13/14、412x915 Android）下进行真机仿真测试。
- **断言标准**：
  - 封存卡片标题必须在 375px 宽度下单行完整展示；
  - 核心解锁按钮内部文字必须单行对齐无断行；
  - 所有标签胶囊必须单行，不发生字内断裂；
  - 页面总宽度不超出视口，横向 `overflow-x` 保持纯净无滚动条。

## Out of Scope

- 不重写后台 Ops 管理大盘的前端逻辑；
- 不变动题库内容或评分精算数学模型；
- 不升级或改动核心依赖版本。
