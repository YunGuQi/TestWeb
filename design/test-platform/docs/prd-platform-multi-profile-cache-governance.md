# PRD: 全平台测试多画像缓存隔离与结果锁死统一治理规范

## Problem Statement

在排查中发现，除 EMO 测试外，平台上的 `destiny-lover`（命定恋人）、`family-origin`（原生家庭人生剧本）以及 `love-species`（恋爱物种）同样存在客户端 `localStorage` 缓存未做画像隔离的问题。用户在设备上核销卡密后，旧画像分析文本在二次答题时强行覆盖新画像，导致命定恋人雷区锁死、原生家庭剧本蜕变长文锁死，恋爱物种更存在已解锁状态下新物种内容变空白的严重体验缺陷，极易引发公私域负面评价与客诉。

## Solution

在全平台彻底落地**方案 A（一码全通 · 设备级解锁 + 多画像独立键槽字典缓存 + 严格渲染守卫 + 新画像静默补拉）**：
1. **多画像字典化存储**：统一各业务线的 `localStorage` 缓存协议，由扁平旧结构升级为包含 `profiles[key]` 字典槽的标准化结构；
2. **严格画像校验守卫**：渲染层核心分析切片严格校验 `unlockedData.key === result.key`，不匹配时决不渲染旧文案；
3. **新画像静默补齐**：对于已激活设备，测出新画像时由前端复用设备核销凭据自动静默拉取新画像切片并缓存，保证免密丝滑体验。

## User Stories

1. As a 命定恋人已付费测试者, I want 重新测试测出不同恋人画像时, so that 看到的致命雷区、单身吸引法和初遇微镜头与新恋人完全一致，绝不串乱。
2. As a 原生家庭已付费测试者, I want 重新测试测出不同剧本时, so that 看到的大女主蜕变长文与新剧本完全一致。
3. As a 恋爱物种已付费测试者, I want 重新测试测出新物种时, so that 新物种的照顾指南与场景解析正常解锁展示，而不是直接变成空白。
4. As a 运营团队, I want 一码多测顺畅运转且绝无张冠李戴, so that 极大降低差评率与售后沟通成本。

## Implementation Decisions

1. **命定恋人 (`destiny-lover`) 改造**：
   - 升级 `verified_destiny-lover` 为包含 `profiles[key]` 结构的字典；
   - 致命雷区、恋爱指南、初遇特写取值全面接入 `activeUnlocked` 守卫；
   - 挂载检测到新画像未缓存时静默请求 `/api/verify` 补全。
2. **原生家庭 (`family-origin`) 改造**：
   - 升级 `verified_family-origin` 为包含剧本 ID 的 `profiles[key]` 结构；
   - 第 340 行大女主蜕变长文与当前剧本 ID 强绑定；
   - 挂载检测到新剧本未缓存时静默补全。
3. **恋爱物种 (`love-species`) 改造**：
   - 升级 `verified_love-species` 为多物种缓存；
   - 修复检测到新物种时将 `unlockedData` 置空导致空白的 Bug，改为自动静默补拉新物种数据。

## Testing Decisions

1. **各测试跨画像一致性验证**：
   - 分别模拟命定恋人、原生家庭、恋爱物种多次答题，确保各自新画像的分析文本完全匹配。
2. **未解锁安全边界验证**：
   - 确保未解锁设备均无法通过 F12 白嫖深度分析。

## Out of Scope

- 商业定价体系变动；
- 数据库 schema 迁移（纯前端与现有核销接口联动）。
