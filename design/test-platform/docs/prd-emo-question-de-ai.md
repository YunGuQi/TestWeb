# PRD: 深度情绪内耗测试题库去AI感重构与宝塔增量部署规范 (Spec)

## Problem Statement

当前线上运行的“深度情绪内耗测试（安安心灵便利店 · 情绪消费账单）”在题库体验上存在以下核心痛点：
1. **词面泄密与AI同义词泛滥**：针对【深夜复盘家】等画像，选项大量使用“回忆”、“复盘”、“反复揣摩”、“分析”、“记好几天”等概念词，做题者无须思考即可猜中判定结果，体验如同做小学生连线题，丧失心理探索欲。
2. **病症阶梯化排布**：同一题目的选项按“重度/中度/轻度/不内耗”排列，容易激发用户的防御机制与伪装心理，做完后自尊受挫、缺乏自传播动力。
3. **顺位惯性**：各维度选项位置存在一定的规律性，缺乏随机打散。
4. **部署与数据安全隐患**：本地 Windows DLP 环境下打包易造成 CSS 样式加密失效；宝塔部署需确保不破坏线上生产数据库。

---

## Solution

严格依据操盘手为为（小满）《第二版方案》与最新沉淀的《02_测试设计_2_题库去AI感与通用化规范.md》实施端到端重构：
1. **禁词硬审查**：彻底清零全卷 80 个选项中的 AI 概念词，转换为日常生活化表达。
2. **平行处事哲学**：将选项重构为 4 种合情合理的成熟处事态度，不搞病理审判，用户凭直觉作答，后台静默加权。
3. **双短语律排布**：统一采用“具体动作（4~6字） + 心理落脚点（6~10字）”的匀称句式。
4. **真随机混维**：彻底随机打散 A/B/C/D 顺位映射。
5. **部署全链路闭环**：本地无 Turbopack 构建 + 内联 CSS 注入 + `pack.py` 打包明文增量包 + 宝塔热更部署（严禁覆盖生产 `dev.db`）。

---

## User Stories

1. As a 测试答题用户，我希望在阅读题目选项时看到的是自然、体面的生活选择，而不是被当作病人审判，以便我能毫无心理防备地凭第一直觉作答。
2. As a 测试答题用户，我希望选项没有明显的“复盘、内耗、回忆”等标签词泄密，以便让我对最终生成的测评结果保持强烈的神秘感与期待感。
3. As a 测试答题用户，我希望每个选项的长短和语气对称协调，以便获得流畅舒适的阅读答题体验。
4. As a 具有反刍倾向的用户，我希望在选择“习惯向内探寻、想把细节理清楚”的体面选项后，依然能准确命中【深夜复盘家】画像，以便获得深度共鸣。
5. As a 运营管理者，我希望题库更新后，底层的 10 大画像归一化打分引擎依然保持均衡健康的触发概率（单画像占比 8%~15%），避免评论区翻车。
6. As a 运维人员，我希望部署到宝塔服务器的过程为纯明文轻量增量包，且不会意外覆盖生产环境真实用户的答题记录与卡密流水。

---

## Implementation Decisions

1. **题库数据契约 (Data Contract)**：
   - 保持 `Question` 与 `Option` 数据模型向下兼容，保留 `id`, `text`, `billName`, `senScore`, `rumScore`, `plsScore`, `bndScore` 字段结构不变。
   - 仅对 20 道题目的 80 个选项的 `text`、`billName` 进行去 AI 感重构，并重置各题选项的维度位置。
2. **算法一致性保证 (Algorithm Locality)**：
   - 各维度的分值总和与理论最高值（maxSen=57, maxRum=77, maxPls=44, maxBnd=80）保持稳定，确保 Z-Score 计算无偏移。
3. **构建与防泄密 (Build & Packaging)**：
   - 采用标准 Next.js 构建输出到 `.next`。
   - 执行 `pack.py` 增量打包，仅包含 `.next`, `public`, `prisma`, `app`, `lib`，排除 `node_modules` 与缓存，输出明文 `deploy.zip`。
4. **宝塔部署安全 (Production Safety)**：
   - 部署时保留线上服务器原有 `prisma/dev.db`，通过文件替换 `.next` 与应用代码实现热更。

## Testing Decisions

1. **算法离线仿真验证**：
   - 编写并运行 Python 离线模拟脚本，执行典型人格路径测试，验证【深夜复盘家】及其他 9 类画像的可达性与权重平衡。
2. **构建与类型验证**：
   - 执行本地 `npm run build`，确保 TypeScript 检查零警告、零报错。
3. **打包包体审查**：
   - 检查 `deploy.zip` 文件，确认关键 CSS 文件为明文（无 `%TSD-Header%` 乱码标记）。
4. **线上回归测试**：
   - 线上访问 `test.mutong-xhs.top/emo`，抽检题面并走通全题答题出票流。

---

## Out of Scope

1. 暂不变更 20 道题目的核心场景题干（保持职场、社交、独处等经典公约数场景）。
2. 暂不修改数据库 Prisma Schema 结构与字段类型（Schema 冻结）。
3. 暂不改动前台小票打印与卡密鉴权逻辑。
