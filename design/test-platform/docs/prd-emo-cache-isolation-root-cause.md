# PRD: EMO情绪测试多画像缓存隔离与结果锁死根治规范

## Problem Statement

当前在 EMO 情绪内耗测试 (`/emo`) 中，用户首次使用激活码完成测试并解锁后，其设备本地 `localStorage` 全局写入了单次测试的深度分析切片。当该用户进行二次测试、切换选项并推导出全新画像（例如从【情绪断电绝缘体】转变为【人间铁壁】）时，前端结果页无条件将旧画像的分析文本塞入页面状态，导致“顶部标题显示新画像，但下方深度心理解码、核心心智金句、致敏场景等仍锁死为旧画像”的严重张冠李戴（跨画像污染）问题，极大损害测试的专业信赖度并引发客诉。

## Solution

在客户端实现**设备级全通激活 + 多画像独立键槽缓存隔离（方案A）**：
1. **多画像字典存储**：将本地缓存从单一结果对象升级为按画像唯一标识（`result.key`）独立分槽存储的字典结构；
2. **严格画像校验守卫**：渲染层深度分析文案仅当缓存画像标识与本次测试结果严格一致时才予以挂载，物理杜绝张冠李戴；
3. **静默画像切片补全**：若当前设备处于已激活状态但尚未缓存当前新画像的付费切片，前端利用已有合法设备凭据向核销服务端发起静默补拉，实时获取新画像专属深度数据，确保一码畅玩、复测体验丝滑。

## User Stories

1. As a 已付费用户, I want 在重新答题测出不同性格画像时, so that 能看到与新画像完全匹配的深度心理解码、金句与致敏场景，而不是上一次测试的残留旧文案。
2. As a 已付费用户, I want 在重新答题测出新画像后无需重复掏钱或重新输入卡密, so that 能够顺畅查看自己的新性格全景分析，享受设备级买断权益。
3. As a 未付费新用户, I want 在未输入有效卡密前, so that 后 70% 的深度心智金句与处方保持安全骨架屏加密，无法通过简单的前端查看获取商业机密。
4. As a 运营人员, I want 系统杜绝因本地缓存串乱而导致的“标题与内容不符”差评客诉, so that 保障私域与公域口碑稳定。

## Implementation Decisions

1. **缓存协议升级**：
   - 弃用扁平化旧键值，升级为具备版本兼容性、设备激活态、最后核销卡密记录及 `profiles: Record<string, ProfileData>` 字典槽的规范结构。
2. **渲染层绝对隔离**：
   - 在组件内部构建 `activeUnlocked` 防御层：只信任 `unlockedData.key === result.key` 的数据，不匹配时坚决不使用旧画像文案。
3. **静默获取机制**：
   - 利用当前设备在服务端的已核销白名单记录，对于已激活设备静默调用服务端验证端点，平滑返回新画像内容并落入对应画像键槽。

## Testing Decisions

1. **多画像状态切换行为测试**：
   - 预设已激活状态下存在画像 A 缓存，切换至画像 B 时，确认页面标题、标签、金句、场景 100% 同步切换为画像 B 内容。
2. **未解锁安全边界测试**：
   - 清除本地凭证后访问结果页，验证骨架屏与弹窗正常阻断，不泄露任何深度分析字段。

## Out of Scope

- 修改题目内容或修改计分权重引擎算法本身；
- 修改支付流水或激活码生成规则。

## Further Notes

- 该模式完全对齐 `city`（城市测试）的最佳实践，未来可推广至其他测评项目。
