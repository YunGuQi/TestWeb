# 01 — 工作包生成器与「只读一个文件」的开工步骤

**What to build:** 操盘手选定测试与结果范围后，技能能生成**一个**压缩工作包文件，执行者读它就能动笔——不再一份份串行读 7 份技能文档，也不必自己去数据源解析结果字段。工作包同时把「禁止读门禁脚本源码」「禁止 Grep/ripgrep」「禁止读历史发帖文案」三条禁令写进去。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 新增工作包生成器：输入该测试的 `测试画像.md` 与已选结果清单，输出单文件工作包
- [ ] 工作包含以下六块：产出格式（卡片块 + 标注行语法）、已选结果素材（结果名 / 金句 / 结果描述 / 标签 / 日程 / 充电日程 / 相克感，且相克地**不点名**）、本测试红线表（医疗词 / 产品词 / 测试术语 / 封杀词 + 专属弃用词与替代表述）、硬指标清单、四模式与展开五型骨架、禁止事项
- [ ] 素材取自数据源的真实字段；该测试的 `condition` 为 JSON 字符串时须先解析再取用，结果名自带书名号须剥掉
- [ ] 工作包显式写明：**不要读门禁脚本源码**（只执行）、**不要用 Grep / ripgrep / glob**、**不要读任何历史发帖文案**
- [ ] 工作包显式写明：结果素材的统计口径（结果总数、本次选中哪几个，可复现的种子或清单）
- [ ] `SKILL.md` 执行顺序索引里插入「生成工作包」这一步，位置在「读测试画像」之后、「问 A/B/C」之前或同段
- [ ] 工作包体积控制：24 卡批次下不超过 20k 字符（实测基准 19.6k）
- [ ] 产物默认落 `.scratch/<slug>/`，不进 `design/product-docs/<测试>/docs/`
- [ ] 端到端验证：同一批 24 卡，执行者的首次读取只有工作包一个文件（工具调用中无其他文档读取、无搜索调用）
