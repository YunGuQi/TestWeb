## Problem Statement

操盘手现在**不敢加量**。`xhs-note-copywriter` 的产出速度是：

- **A/B 24 卡：15 分 33 秒**（2026-09-21 串行实测，单子代理）
- **C 全量 64 卡：按同一机制线性外推 ≈40 分钟以上**

而 C 全量是技能自己规定的口径（§6.1：结果数 × 四模式，16 结果 = 64 篇），也就是说**技能一上线就自带一个跑不动的默认路径**。实测拆解显示，时间根本不在写作上：

1. **9 次串行工具调用（约 8 分钟）花在「读文档 + 找文件」**：7 份技能文档 35.8k 字符（≈22.4k token）被一份份串行读入，每读一份都重算一次累积上下文；还误读了 53.5 KB 的 `scripts/gate.js` 源码（技能只要求「执行」它，从没要求读它），单次约 1.4~1.8 万 token。
2. **6 次返工全来自「跨卡判据」**：`#21` 同模式主展开型超限、封面级差不足、超宽行——这些都是**写完全批才能算出来**的配额，靠事后跑门禁才发现，于是「写 24 张 → 报错 → 改 8 处」。
3. **`gate.js` 单次运行只要 0.51 秒**，而生成要 15 分钟：**验证比生成便宜 1800 倍，却在用最贵的资源做试错**。
4. **分片级判据会误报**：把批次拆开并行后，worker 拿到的是「全批级」判据（如 `#16` 乙类占比 ≥1/3），在只有 4 张卡的分片上**数学上不可能成立**，worker 被迫为一条假 ❌ 停手解释。

结果：一次 24 卡交付 ≈16 分钟，全量 ≈40 分钟，操盘手的选择只有「少写」或「等」。

## Solution

把 2026-09-21 P1 对照实验验证过的三层机制**固化进技能**（实测 24 卡墙钟 15 分 33 秒 → **7 分 37 秒**，门禁 0 ❌ / 0 ⚠️）：

- **输入层 · 工作包**：把「画像 + 本次口径 + 已选结果素材 + 红线表 + 硬指标 + 四模式骨架」压成**一个文件**，执行者只读它。子代理的必读输入从 7 份 35.8k 字符降到 **1 份 19.6k 字符（−45%）**，并明确**禁止读 `gate.js` 源码**、**禁止 Grep/ripgrep**（`.agent/**` 被忽略，搜索恒返回空，实测白烧 3 次调用）。
- **计划层 · 分配表 + 计划级预检**：动笔**之前**把 12 个维度（模式 / 取材型 / 起手型 / 展开型 / 档 / 缺口型 / 整活 / emoji / 封面行数 / 目标末行字数 / 钩子形态 / 互动钩子词）一次排定，用 `plan-gate.js` 在 **0.5 秒**内验完 `#9 #16 #17 #20 #21 #23a #23b #23c #24 #25 #26` 与「换型不许同构」——**让跨卡判据从「事后返工」变成「一开始就撞不到」**。实测返工从 6 次降到 2 次。
- **执行层 · 分片并行 + 分片级门禁**：1 worker = 1 结果 × 四模式（同结果四张出自同一支笔，保住口音一致）；`gate.js --shard` 在分片级把**全批级判据降级为 ⚠️ 提示**（不静默，避免 worker 对真问题失明），合并后由主代理按全批判定。

同时按批准的口径变更收敛 C 全量的成本：**C 全量 = 主推 6 结果 × 四模式（24 篇）过完整门禁 + 其余结果走技能既有的「长尾降级」兜底**（取同测试已定稿骨架，只换 `title` / `quote` / `tags` 三个专有字段，**不进 feed 主推位**），而不是 64 篇全量过门禁。

## User Stories

1. 作为操盘手，我希望 A/B 24 卡的交付墙钟压到 **≤7 分钟**，这样一天能排两批而不是一批。
2. 作为操盘手，我希望提速**不是靠放松门禁**换来的，这样提速后文案质量不下滑。
3. 作为操盘手，我希望执行者只读**一个**工作包文件，这样它不会一份份串行读文档、把 8 分钟烧在读取上。
4. 作为操盘手，我希望工作包里已经把画像、口径、素材内联好，这样执行者不必自己去 `lib/*-data.ts` 解析 `condition` 这层 JSON 字符串。
5. 作为操盘手，我希望工作包明确禁止读 `gate.js` 源码，这样不会有人把 53.5 KB 的脚本读进上下文（技能只要求执行它）。
6. 作为操盘手，我希望工作包明确禁止 Grep / ripgrep，这样不会在 `.agent/**`（被 gitignore、搜索恒返回空）上白烧调用。
7. 作为操盘手，我希望**动笔前**就拿到一张 12 列分配表（模式 / 取材型 / 起手型 / 展开型 / 档 / 缺口型 / 整活 / emoji / 封面行数 / 目标末行字数 / 钩子形态 / 互动钩子词），这样跨卡配额是「排出来的」而不是「事后改出来的」。
8. 作为操盘手，我希望这张表由脚本自动排（拉丁方轮转），而不是靠人拍脑袋，这样哪个测试、多少个结果都能稳定生成。
9. 作为操盘手，我希望分配表在动笔前被 `plan-gate.js` 预检，且**不绿不许动笔**，这样 `#21` 类返工在开写前就被拦掉。
10. 作为操盘手，我希望 `plan-gate.js` 顺带核对「档位归属表」与 `gate.js` 的 `MOOD_TABLE` 是否一致，这样档名写错不会让 `#23a` / `#24` 静默空转。
11. 作为操盘手，我希望 `plan-gate.js` 检查「同一模式的 ≤2 张换型必须互不相同」，这样不会再出现「字面达标但 8 张换型全用同一个备选型」的同构（P1 实验前的真实盲区）。
12. 作为操盘手，我希望分配表里有「目标末行字数」一列，这样 `#22d`（末行齐整）不会因为缺口型分配失手而恶化。
13. 作为操盘手，我希望分配表里的钩子形态**直接填 `gate.js` 词库里的原句**（如 `有没有人`），这样不会因为写「有没有同款」这类同义改写而漏判。
14. 作为操盘手，我希望同一钩子句式**不许全批复用**，这样固定句式不会自己吃掉 `#7` 跨卡重复配额（P1 实测：3 条重复里 3 条都是钩子句）。
15. 作为操盘手，我希望 1 个 worker 负责「1 个结果 × 四模式」，这样同一结果的四张出自同一支笔，口音不分叉。
16. 作为操盘手，我希望**不要**按「1 模式 = 1 worker」切分，这样四张卡不会变成四支笔写的。
17. 作为操盘手，我希望分片 worker 跑门禁时全批级判据降级为 ⚠️ 提示而不是硬 ❌，这样它不会为一条数学上不可能成立的分片判据停手。
18. 作为操盘手，我希望分片级判据**降级为提示而非静默**，这样 worker 还能上报「疑似全批级问题」由主代理合并后判。
19. 作为操盘手，我希望合并后由主代理按全批重跑一次门禁，这样分片级放过的全批级问题仍会被拦。
20. 作为操盘手，我希望分片文件能被脚本自动装配（补结果清单、发布排期表、评论区首条），这样我不必手工拼 24 张卡。
21. 作为操盘手，我希望结果清单 / 排期表 / 评论区首条由装配器统一生成，这样排期规则（6 天 × 每天 4 篇、当天结果与模式都不重复）不会因人工拼装出错。
22. 作为操盘手，我希望 A/B 24 卡**默认走并行分片**，这样日常交付就是快的。
23. 作为操盘手，我希望**≤12 卡时退回串行**，这样小批量不必付 6 路工作包的 token 溢价。
24. 作为操盘手，我希望子代理不可用时能退回串行，这样技能在单线程环境下仍然可用。
25. 作为操盘手，我希望 C 全量的口径改成「主推 6 结果 × 四模式过完整门禁 + 其余走长尾降级兜底」，这样全量不再是 40 分钟的不可执行路径。
26. 作为操盘手，我希望长尾降级明确「只换 `title` / `quote` / `tags` 三个专有字段」且「不进 feed 主推位」，这样全量兜底稿的质量边界是清楚的。
27. 作为操盘手，我希望 C 全量的长尾降级**沿用技能既有的兜底路径**（§六 第 5 步），而不是新发明一套机制。
28. 作为操盘手，我希望这次提速**不改动任何门禁阈值**，这样既有批次不会因提速而返工。
29. 作为操盘手，我希望 `gate.js --selftest` 在改造后仍是 **41/41**，这样我知道判据本身没被改坏。
30. 作为操盘手，我希望 2026-09-21 的 24 卡靶子**仍然报 ❌**，这样「门禁没被削弱」是被验证的而不是被声称的。
31. 作为操盘手，我希望 `--lint-docs` 悬空指针仍为 **0**，这样新增脚本与文档没有打断既有指针。
32. 作为操盘手，我希望提速机制**写进 `SKILL.md` 的执行顺序索引**（工作包 → 分配表预检 → 落笔），这样新会话照索引走就能复现 7 分钟。
33. 作为操盘手，我希望「执行模式」的两态（串行 / 并行分片）在 `SKILL.md` 里有明确判定条件，这样执行者不必猜该用哪种。
34. 作为操盘手，我希望**停机闸门不变**（开工前 1 次 A/B/C 选择、交付后 1 次汇报），这样提速不以增加我的交互次数为代价。
35. 作为操盘手，我希望本轮改动**只落在唯一真源** `.agent/skills/xhs-note-copywriter/`，这样三副本 junction 自动同步、不产生漂移。
36. 作为操盘手，我希望工作包与分配表**只落在 `.scratch/`**（临时），这样交付目录 `design/product-docs/<测试>/docs/` 里只有发帖稿，不被中间件污染。
37. 作为操盘手，我希望实测墙钟被记进回归记录，这样「提速是真的」有可复核的数字。
38. 作为操盘手，我希望知道这轮改动的**代价**（token 总量约 3~4 倍），这样我能在批量与成本之间做选择。

## Implementation Decisions

- **改动范围**：只改唯一真源 `.agent/skills/xhs-note-copywriter/`（`SKILL.md` + `references/` + `scripts/`）。`.claude/skills`、`.cursor/skills` 是指向它的 junction（工单 08 已建成），**不在镜像路径里直接改**。
- **三层机制**：
  - **工作包生成器**（新增脚本）：输入该测试 `docs/测试画像.md` + 数据源里已选中的结果，输出单文件工作包。内容 = 产出格式 + 已选结果素材（含 `condition` 解析后的 `tags` / `schedule` / `curePrescription` / `toxicCity`）+ 本测试红线表 + 硬指标清单 + 四模式与展开五型骨架 + 禁止事项（禁读 `gate.js`、禁 Grep/ripgrep、禁读历史发帖文案）。
  - **分配表生成器 + 计划级预检**（新增两个脚本）：生成器按拉丁方轮转排出 12 列分配表（档 / 整活做轮转，emoji 与钩子形态受配额约束，封面行数在 2~4 间混排，目标末行字数在 3/7/11/14 间混排）；预检器验跨卡配额、验「换型不许同构」（全批换型种类 ≥3 且单组换型不重复）、并核对档位归属表与门禁脚本执行副本是否逐名相等。
  - **分片级门禁**（在既有门禁脚本上加参数，不改判据）：新增 `--shard`，把**全批级**判据降级为 ⚠️ 提示。分级清单：
    - 单卡级（分片必须清零）：封面/标题字数、单行宽度、产品词、测试术语、医疗词、封杀词、封面错落、首行不复述、结果名入封面标题、伪补刀、首行与标题公共子串、标签数、单卡封面行数与级差、短行率。
    - 全批级（`--shard` 下降级为 ⚠️）：跨卡重复整句、四档皆有、乙类占比、单型占比、前 2 位标签恒定、同模式主展开型分布、末行齐整、emoji 按档、末行散布、句末标点密度、整活配额、互动钩子、全批封面行数恒定。
- **判据变更**：**阈值一条不动**。只新增①`--shard` 分级；②「换型不许同构」这一条**计划级**约束（落在分配表生成与预检，不进 `gate.js` 判定）。`gate.js` 的 `MOOD_TABLE`、词表、`#1~#26` 阈值全部不变。
- **执行模式两态**（写进 `SKILL.md`）：串行 = ≤12 卡或子代理不可用；并行分片 = A/B 24 卡或 C 全量，1 worker = 1 结果 × 四模式。
- **C 全量口径变更**（已批准）：主推 6 结果 × 四模式 = 24 篇走完整门禁 + 其余结果走**既有**长尾降级（§六 第 5 步：取同测试已定稿骨架，只换 `title` / `quote` / `tags`），长尾稿只作结果页兜底、不进 feed 主推位。文档里同时保留「全量过门禁」作为可选项而非默认。
- **停机闸门不变**：仍是开工前 1 次（A/B/C 选择）与交付后 1 次（汇报）。
- **产物落位**：工作包、分配表、分片、装配稿一律落 `.scratch/<slug>/`；只有最终发帖稿落 `design/product-docs/<测试>/docs/YYYY-MM-DD_发帖文案.md`。
- **代价与边界**：6 路并行 × 每路约 12k token 工作包 ≈ 串行单路总量的 3~4 倍 token；换来墙钟约 2 倍提升。≤12 卡退回串行。
- **不引入**：不新增第五档、不改整活轴定义、不改双位/三层/取材七型/展开五型、不动评论区首条（仍是每测试一次预计算的常量）。

## Testing Decisions

- **什么是好测试**：只测外部可观察行为。本改造的外部行为 = ① 拿一份真实发帖文案 md 喂给门禁脚本，看它报什么；② 拿一份分配表喂给计划级预检，看它拦不拦；③ 端到端跑一批，看墙钟与门禁结果。
- **主回归靶子（既有 fixture）**：`design/product-docs/大女主觉醒测试/docs/2026-09-21_发帖文案.md`（24 卡，真实产出）。改造后**必须仍报 ❌**（`#21` 三处 + `#22` 相关）；变全绿即判据被削弱。
- **判据自检（既有先例）**：`gate.js --selftest`，现为 41 条，改造后**仍须 41/41**。
- **计划级预检的测试**：以 P1 实验的分配表为夹具，验「故意把某模式主型改成 5/6」「故意把 6 张换型全填同一型」「故意写一个未登记档名」三种情形都必须被判失败。
- **分片门禁的测试**：以 P1 的 `shard-r6.md` 为夹具（它在全批判定下 4 张卡乙类 1/4 不达标），验 `--shard` 下该条**降级为 ⚠️ 且不再判失败**，而合并稿上仍会判 ❌。
- **指针扫描测试**：`--lint-docs` 跑全库，改造后期望悬空指针 **0**；档位归属表双向核对 ✅。
- **被测模块**：门禁脚本（既有，唯一有执行逻辑的旧模块）+ 新增的工作包生成器、分配表生成器、计划级预检器（三者均有可执行逻辑，各自需要 selftest 或夹具用例）。
- **端到端测速**：同一批 24 卡（种子 `20260921`，6 结果 × 四模式）复跑，记录墙钟并与基线 15 分 33 秒对照，目标 ≤7 分钟。

## Further Notes

- **P1 实验全部产物**（可复核）：`.scratch/copywriting-skill-refactor/exp-P1/` —— `workpack.md`（工作包）、`plan.md`（24 行分配表）、`plan-gate.js`（计划级预检，49 项 ✅ / 0 ❌ / 0 ⚠️）、`assemble.js`（装配器）、`shard-r1~r6.md`（6 路分片）、`out/sample-city-24-P1.md`（合并稿，0 ❌ / 0 ⚠️）。
- **实测基线（改造前）**：A/B 24 卡 **15 分 33 秒** ｜ 子代理工具调用 **26 次**（Read 10 / Grep 3 / Write 1 / StrReplace 8 / Shell 4） ｜ 必读输入 **7 份 35.8k 字符 ≈22.4k token** ｜ 门禁单次 **0.51 秒** ｜ `--selftest` **0.40 秒**。
