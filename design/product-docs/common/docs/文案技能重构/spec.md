# 文案技能拆分与门禁修复 · PRD

> 状态：`ready-for-agent` ｜ 来源：2026-09-21 对话（Phase 3 文案体系审计 + 需求对齐）
> 落盘位置说明：`to-tickets` 默认把本地工单放 `.scratch/<slug>/`（已被 `.gitignore` 忽略）。本 PRD 与工单需要跨会话长期引用，故落在受版本控制的 `design/product-docs/common/docs/文案技能重构/` 下。

---

## Problem Statement

操盘手依赖 `xhs-auto-operator-v7` 的 Phase 3 批量产出小红书发帖文案（单测试一次 24 篇起）。当前存在四个从用户视角可见的问题：

1. **门禁跑不起来，事实上被绕过。** SOP 指定的门禁命令全部指向已不存在的 `xhs-auto-operator-v5/scripts/`（技能改名 v5→v7 时断了），全库 10 处死链。而 SOP 自己写着「跳过自检直接交付 = 交付未验收的文案」——一条跑不通的命令，结局就是被跳过。
2. **门禁会给出假绿灯。** 门禁 `#21`（同一模式跨结果，主展开型 ≤4/6）在脚本里只打印不判定。实测 2026-09-21 的 24 卡批次里，模式一 6/6、模式二 6/6、模式三 6/6 全部违规，脚本仍报「✅ 机械项全通过」。
3. **文案的「AI 感」没治好，而病因是 SOP 自己的配额体系。** 报告腔在 09-21 批次已被治好，但整齐腔仍在：24 卡 emoji 为 **0**，末行 ≤8 字短句 **19/24**，「我说」65 次（涉 18 卡）、「我说＋她说」合计 93 次，年龄递进排比与「我说/她说」交替对话成为跨卡指纹。门禁只查**逐字**重复（1.6% 达标），对句法同构完全失明。
4. **分发环节整段空白。** 24 卡共用同一条评论首条、前 2 位标签全批恒定，全库无任何排期/发布节奏规范；互动钩子只落在 1/4 的卡。内容合格不等于分发合格。

同时，用户已明确 Phase 3 只需**一种形态**（纯色大字封面 + 零编辑一键复制文本卡片），「形态 2 答题图文实装流」及其 `生成排版图.html` 依赖整体废弃。

用户要的不是"把 SOP 写得更花"，而是在**不必逐篇人审**的前提下稳定产出「像人写的」文案；并把门禁从"改名就断、结论还假"修成"改名不坏、结论可信"的工具。

## Solution

把 Phase 3 从 `xhs-auto-operator-v7` 中**拆出为一个独立技能** `xhs-note-copywriter`（名字不带版本号），并对它做一次结构性修剪：

- **结构**：单文件 539 行的 `03_笔记文案篇.md` 拆成 6 份按分支组织的参考文档 + `scripts/gate.js`，原 v7 的 Phase 3 三份文件压缩成一行指针。
- **单真源**：同一含义在多处复述的清单（产品词/医疗词/封杀词、零历史依赖铁律、正文零产品词、emoji 规则）各自收敛到唯一一家。
- **门禁**：脚本迁到无版本号的稳定入口；真修 `#21`；新增句式同构、野性配额、整活配额三组判据（**第一轮先做灰区 ⚠️，跑通一批后收紧为硬失败**）；新增 `--lint-docs` 指针可达性扫描，扫全库 `node "…"` 与 `.md` 链接，防死链复发。
- **整活轴**：新增一条与情绪四档**正交**的「整活」轴（自嘲式玩梗、可转发幽默），只允许落在**冷笑 / 解气**两档；破防 / 认命保持低气压。口音表增「允许整活」列。
- **分发**：新增「分发与排期」一篇，含互动钩子配额与多图配置。
- **形态**：只保留「纯色大字封面 + 零编辑一键复制文本卡片」，并把「纯色大字封面」从空头承诺补成真规范（字号层级、行距、留白、安全区、强调色落位、行数区间、行首对齐）。
- **同步**：`.claude/skills` 与 `.cursor/skills` 改为指向 `.agent/skills` 的 junction，从结构上消灭三副本漂移。

## User Stories

1. 作为操盘手，我希望门禁能用一条命令跑通，这样我不必记住技能当前叫什么版本。
2. 作为操盘手，我希望技能改名后门禁命令不会断，这样我不必每次改名都全库搜替换。
3. 作为操盘手，我希望门禁在判到违规时给出 ❌，这样我不必自己逐条核对。
4. 作为操盘手，我希望门禁能抓出「同模式跨结果全是同一个展开型」，这样模具化会被当场拦住。
5. 作为操盘手，我希望门禁能抓出「全批末行都是短句」「全批零 emoji」这类整齐腔，这样 AI 感可以在交付前被拦截。
6. 作为操盘手，我希望门禁能抓出「单卡『说』字超过阈值」这类对话腔指纹，这样五张卡不会读起来像同一个人写的。
7. 作为操盘手，我希望新判据第一轮只做灰区提示，这样现有 24 卡不会因新规则大面积返工。
8. 作为操盘手，我希望灰区提示可以在一批跑通后收紧为硬失败，这样判据能逐步硬化。
9. 作为操盘手，我希望门禁能扫描全库文档里的命令与链接，文件不存在就报错，这样死链不会再次累积到 10 处才发现。
10. 作为操盘手，我希望门禁脚本放在不带版本号的路径下，这样它是长期稳定入口。
11. 作为操盘手，我希望门禁脚本自带判据回归自检（`--selftest`），这样改动判据后我能立刻知道有没有改坏。
12. 作为操盘手，我希望文案技能可以单独被唤醒，这样我只要写文案时不必走完账号基建→爆款对标→测试研发。
13. 作为操盘手，我希望写文案时视野里没有 Phase 4（千帆店铺图），这样注意力不会被拽走。
14. 作为操盘手，我希望同一个含义在 SOP 里只有一处家，这样我改规则时只改一个地方。
15. 作为操盘手，我希望产品词/医疗词/封杀词清单只有一份，这样不会出现"文档说能写、脚本说不行"。
16. 作为操盘手，我希望「正文零产品词」只在红线篇说一次，这样写作技巧篇可以专注讲正向做法。
17. 作为操盘手，我希望「零历史依赖铁律」只在一处声明，这样新技能不会一开篇就重复三遍。
18. 作为操盘手，我希望 emoji 的使用规则明确作用域（正文 vs 评论区首条），这样不会出现"一边禁一边要留"的矛盾。
19. 作为操盘手，我希望冷笑 / 解气两档的文案可以用整活腔（自嘲玩梗、可转发幽默），这样文案能覆盖「好笑、想转发」这一层分享动机。
20. 作为操盘手，我希望破防 / 认命两档保持低气压，这样不会在用户最脆弱的时刻玩梗翻车。
21. 作为操盘手，我希望口音表增加「允许整活」列，这样每个结果该不该整活是查表得到、不是现场拍脑袋。
22. 作为操盘手，我希望整活只作为第二条轴、不新增第五档，这样情绪档位模型不被破坏。
23. 作为操盘手，我希望有排期与发布节奏规范，这样一天连发 24 篇同标签笔记不会触发风控。
24. 作为操盘手，我希望有互动钩子配额，这样四张卡里至少不止一张在引导评论。
25. 作为操盘手，我希望有「纯色大字封面」的真规范（字号层级、行距、留白、安全区、强调色落位），这样封面不再只有"≤20 字"这一个约束。
26. 作为操盘手，我希望封面有行数区间与行字数级差要求，这样错落要求从"有一行 ≤4 字"升级为可视化的真错落。
27. 作为操盘手，我希望形态 2（答题图文实装流）及其 `生成排版图.html` 指针整体删除，这样不再有指向不存在文件的承诺。
28. 作为操盘手，我希望 `04_视觉物料_*` 里追记封面图的文件名改为实际存在的 `docs/YYYY-MM-DD_发帖文案.md`，这样追记不会写进空气文件。
29. 作为操盘手，我希望 `.claude/skills`、`.cursor/skills` 与 `.agent/skills` 物理上是同一份内容，这样新技能只需落盘一次。
30. 作为操盘手，我希望同步是结构性的（junction）而非靠人工跑同步脚本，这样漂移不可能发生。
31. 作为操盘手，我希望拿 2026-09-21 的 24 卡真实批次当回归靶子，这样新判据"能不能真抓出东西"是可验证的。
32. 作为操盘手，我希望回归的验收标准是「新脚本必须抓出旧脚本漏掉的问题」，这样判据写废了会被立刻发现。
33. 作为操盘手，我希望 `#21` 的判据从"只打印"变成"真分组计算"，这样它对得上 SOP 表里的定义。
34. 作为操盘手，我希望 `.gitignore` 保护这两个镜像目录，这样不会有人把 227 MB 镜像提交进仓库。
35. 作为操盘手，我希望 v7 的 Phase 3 保留一行指针指向新技能，这样从旧流程进来的人能找到新家。

## Implementation Decisions

- **新技能标识**：`xhs-note-copywriter`。**不带版本号**——版本号编码进路径正是 `v5→v7` 断链事故的根因。该名避开 `.mcp.json` 中已占用的 `xhs-copywriter`（MCP 服务器名）。
- **目录结构**：新技能落盘在 `.agent/skills/xhs-note-copywriter/`（单一真源），含 `SKILL.md` + `references/`（6 份）+ `scripts/gate.js`。
- **参考文档切分**（按分支，不按篇幅）：
  - `00_画像与档位.md` — 画像三区块 / 口音表（含新增「允许整活」列）/ 情绪四档
  - `01_双位与正文.md` — 双位 / 取材七型 / 起手八型 / 缺口四型 / 正文三动作 / 展开五型 / 去指纹
  - `02_四模式.md` — 四大模式 + 整活轴注入点
  - `03_红线与门禁.md` — 红线三分区（唯一真源）+ 门禁表 + 检验法（吸收原 `03a`）
  - `04_分发与排期.md` — 排期节奏 / 多图配置 / 互动钩子配额（新增）
  - `05_示例库.md` — 原 `03b` 迁入
- **门禁脚本入口**：稳定路径 `scripts/gate.js`（不再带版本号）。
- **门禁判据变更**：
  - `#21` 改为真按模式分组计算（同模式主展开型 ≤ 组内 2/3）。
  - 新增 `#22` 句式同构（排比骨架三连 / 单卡「说」字计数 / 末行 ≤8 字占比）。
  - 新增 `#23` 野性配额（emoji 按档：破防·认命 = 0，冷笑·解气 **档组内带 emoji 的卡占 1/3~2/3**——2026-09-21 口径明确：既不许零 emoji，也不许齐齐加；末行长度散布；句号密度）。
  - 新增 `#24` 整活配额（冷笑·解气两档须有整活卡；破防·认命带整活标记直接判失败）。
  - 新增 `--lint-docs`：扫全库 `node "…"` 命令与 `.md` 相对链接，目标不存在即失败。
  - **新判据（#22/#23/#24）第一轮只报灰区 ⚠️，不判失败**；跑通一批后由独立工单收紧为硬失败。
- **整活轴设计**：作为与情绪四档**正交**的第二条轴，不新增档位。整活 = 自嘲式玩梗 / 可转发幽默 / 阴阳式身份讽刺。作用域：仅冷笑、解气。
- **形态收敛**：删除形态 2 及其 `生成排版图.html` 指针。Phase 3 唯一交付形态 = 纯色大字封面 + 零编辑一键复制文本卡片（` ```text ` 块，`[封面]`/`[标题]`/正文/标签）。
- **封面规范补齐**：在 `01_双位与正文.md` 或 `03_红线与门禁.md` 补出「纯色大字封面」的可执行视觉规范（字号层级、行距、留白与安全区、强调色落位规则、封面行数区间、行首对齐）。
- **单真源收敛表**：
  | 内容 | 唯一家 |
  |---|---|
  | 产品词 / 医疗词 / 封杀词清单 | `03_红线与门禁.md` |
  | 零历史依赖铁律 | `SKILL.md` |
  | 正文零产品词 | `03_红线与门禁.md`（技巧篇只讲正向做法） |
  | emoji 规则（含作用域） | `03_红线与门禁.md` |
- **v7 处理**：`SKILL.md` 的 Phase 3 三份文件压成一行指针；`03_笔记文案篇.md` / `03a` / `03b` 本体删除，`03c` 脚本迁出。`04_视觉物料_*` 中的 `post_copy.md` 改指 `docs/YYYY-MM-DD_发帖文案.md`。
- **三副本同步**：`.cursor/skills` 与 `.claude/skills` 改为指向 `.agent/skills` 的 **directory junction**（Windows 本地目录无需管理员）。不用真 symlink：`core.symlinks=false`。因 junction 存绝对路径，**仓库换盘符/移动目录后需重跑一键脚本**。
- **Git 侧**：`.claude/skills`、`.cursor/skills` 当前既未被追踪也未被忽略（`git ls-files` = 0），junction 对其隐形；建议在 `.gitignore` 增补两行，防止误提交 227 MB 镜像。

## Testing Decisions

- **什么是好测试**：只测外部可观察行为，不测实现细节。对本改造而言，"外部行为" = **把一份真实发帖文案 md 喂给门禁脚本，看它报什么**。
- **主回归靶子（既有 fixture）**：`design/product-docs/大女主觉醒测试/docs/2026-09-21_发帖文案.md`（24 卡，真实产出）。它同时是**正样本与反样本**：
  - 旧脚本对它报「✅ 机械项全通过」；
  - 新脚本**必须**抓出：`#21` 三处违规（模式一/二/三各 6/6 同展开型）、句式同构（末行 19/24 齐整、零 emoji）、单卡「说」字超阈值。
  - **抓不出来 = 判据写废了**，这是本次回归的核心验收。
- **判据自检（既有先例）**：`gate.js --selftest`，沿用现脚本已有的用例式回归（现为 #15 的 6 条原文示例）。新增判据各自补用例。
- **指针扫描测试**：`--lint-docs` 跑全库，期望改造后悬空指针为 **0**。改造前的死链数（10 处 `v5` 路径）作为反向基线。
- **junction 验证**：改后三个目录 `lstat().isSymbolicLink()` 为真，且穿读同一文件可正常打开。
- **被测模块**：`scripts/gate.js`（唯一有可执行逻辑的模块）。6 份参考文档为规范文本，不做自动化测试，靠 `--lint-docs` 校验其内部链接。

## Further Notes

- 本 PRD 的需求对齐过程见同目录对话记录：四轮 one-question-at-a-time 访谈，结论为 ① 排版指 SOP 自身结构而非测试页 UI；②「野」取激进档（把「好笑/想转发」当一级目标）；③ 整活按档位切（仅冷笑/解气）；④ 结构取模块化拆分（拆独立技能）。
- 可复跑的度量基线（改造前实测值）：emoji **0** ｜ 末行 ≤8 字 **19/24** ｜「我说+她说」**93 次** ｜「我说」涉 **18/24** 卡 ｜ 跨卡逐字重复 **1.6%** ｜ 短行率 **44.3%** ｜ 门禁 `#21` 违规 **3 处**但报全绿 ｜ 悬空指针 **10 处**。
- 改造目标值：emoji 按档受控 ｜ 末行 ≤8 字 ≤12/24 ｜「我说+她说」≤45 次 ｜ `#21` 真报 ❌ ｜ 悬空指针 0 ｜ 门禁一条命令跑通、改名不断。
- 体积事实：三份 skills 树各约 **227 MB**，内容逐字节相同（除 `.agent` 独有的 32 个 v5 归档文件）。故同步必须用**同卷改名**，绝不复制。
- 门禁脚本历史事故：`03a` 曾把封杀词清单复述一遍，与 `03`、与脚本三处各说各话（脚本多出 `前半段`，两处文档都没有）。这直接推出"清单只维护一份"的决策。
