# 文案技能去门禁 · PRD

> 项目代号：`文案技能去门禁`
> 上游：`文案技能重构`（issues 01~08）、`文案技能提速`（issues 01~07，其中 06/07 未完成）
> 状态：需求对齐与计划**均已获批准**，本 PRD 为实现依据

---

## Problem Statement

从使用者（大哥）视角，这套文案技能在最近两轮改造后出现了错位——**任务只是"写文案"，技能却越长越像一套软件工程**：

1. **体量与职责错位**：技能合计 244.8 KB，其中 84 KB（`gate.js` 58.7 KB + `plan-gate.js` 25.7 KB）是**事后校验脚本**——它们不产出任何文案，只负责"交稿后挑错"。

2. **一批判据读者根本看不出**：26 条门禁判据里，`#8` 短行占比、`#16` 乙类占比、`#17` 单型占比、`#21` 主展开型占比、`#22d` 末行齐整、`#23` 末行取值数与极差、`#23c` 句号密度，**全部依赖精确计数或全批统计**。它们之所以"必须用代码"，只是因为模型数不准——而一个读者读文案时从不精确计数。**"必须靠代码判"与"读者看不出"几乎是同一批判据。**

3. **判据精确化诱发"为达标而凑"**：上一轮 P1 实验实测到——为填 `#24 整活配额` 硬塞不好笑的卡，为凑 `#25 钩子数量` 硬凑话术。**凑出来的结果比不达标更难看。**

4. **同一份词表存了三处**：合规词表在 `references/03_红线与门禁.md`、`gate.js`、`xhs-note-analyzer/references/sensitive-words.md` 各有一份。为维护这种冗余，还专门建了 `--lint-docs` 去**双向核对两份实现有没有对上**——这是"为维护冗余而生的工具"。

5. **校验器自己承认它没用**：`gate.js` 头部注释原文即为「**定位: 机械兜底。判的是字面，语义仍由人工判。门禁全绿不代表文案合格。**」

6. **自我评审偏误无解**：写完自己检查会偏向认为"写对了"。机器同样只判字面、抓不住"这篇写砸了"，所以它不是这个问题的解。

**使用者原话**：「为何需要 js 来判断是否有问题，你就是最强大的 AI，为何不能写完笔记文案后，你直接按照清单 md 文档判断是否有问题就行了，就不需要 js 了。」

---

## Solution

把技能从「机器工程」退回「短文档 + AI 判断」，**三类东西各归其位**：

| 类别 | 处置 | 理由 |
|---|---|---|
| **生成器**（备料 / 排程） | **保留** | 它们**不判断任何东西**，只把"动笔前要读的 91.3 KB 文档压成 44.2 KB"、"把跨卡配额一次排死"。这是 Deming 式的"质量做进去" |
| **校验器**（事后挑错） | **删除** | 依赖精确计数与全批统计的判据读者看不出；能看出的判据用清单即可 |
| **检查这件事** | **收敛为一处** | 交给已有的 `xhs-note-analyzer`（审计者立场、对抗姿态、不限字面），并补齐它对本地业务词的覆盖 |

**26 条判据的处置原则：留意图、删配额。**

- **直接删**：读者根本看不出的 7 条（纯统计分布）
- **保留为硬规格**：物理格式型数字（封面/标题字数、单行宽度、封面错落、标签个数、封面行数）——**必须保留且必须内联进工作包**，见 §四.1 更正
- **留意图、删数字**：emoji 按档 / 钩子 / 句式同构 → 改成读者视角问句
- **进清单**：一眼看得出的 13 条 → 写成"看一眼"的检验动作
- **换动作**：跨卡重复整句 → "读完这批，找我意识到自己重复了哪句"
- **迁走**：本业务医疗词 → `xhs-note-analyzer` 词库
- **降级但必留**：低气压档禁止整活 → 清单里写成明确硬要求（不许变成可商量的"有没有敢开玩笑的"）

### 更正 · 两类数字必须分开（2026-09-21 实测发现）

> 原方案把 `#4` 单行宽度、`#12` 封面错落一并归入"数字放松"，**这一步是错的**。后果：工作包不再自足 → 执行者被 §0 禁止读别的文档、却又拿不到规格 → 违规去读 `01` → 初稿 **24/24 张正文行宽超标、8 张封面错落不合格** → **整篇重写，占总耗时 50%**。

| 数字类型 | 例 | 处置 |
|---|---|---|
| **统计分布型** | 短行占比 ≥15% · 乙类 ≥1/3 · 单型 ≤1/4 · 主展开型 ≤2/3 · 末行 ≥5 种取值 / 极差 ≥4 · 句号密度 ≤85% | **删**——代理指标，会诱发"为达标而凑" |
| **物理格式型** | 单行 ≤15 字 · 封面 2~4 行 · 封面总字数 ≤20 · 封面有一行 ≤4 字且一行 ≥6 字 · 标题 ≤20 字 · 标签 =5 | **必须保留，且必须内联进工作包**——它是必须达成的形状，不是可凑的配额 |

**判别口径（一句话）**：这个数字能不能被"凑"出来害人？

- 能凑（多塞整活卡、多塞钩子词、把末行字数配平）→ 统计分布型 → **删**
- 不能凑（一行 18 个字就是超了；封面缺一行 ≥6 字就是不合格）→ 物理格式型 → **留**

**三处真源必须一致**：`01_双位与正文.md` §一 是**写作口径真源**；`03_红线与门禁.md` §7.0 是**交付检查真源**；工作包 §4.0 是**执行者唯一读到的内联副本**。本次回归正是"内联副本被删、另两处还在"，导致口径断链。

## Implementation Decisions

### 分层原则（本次改造的判据）

**生成器 vs 校验器的分野**：

- **生成器** = 备料 + 排程 → 让执行者**少读、少改**。判断为零，不产出 ❌/⚠️。
- **校验器** = 事后挑错 → 让执行者**返工**。

本次只删后者。判据：**一个模块若不含任何判断逻辑、只做信息重组，则保留。**

### 术语统一

技能内统一改称：
- 「门禁」→「自检清单」（涉及 26 条判据的语境）
- 保留「红线」（§四 擦边红线三分区）作为写前约束的称呼
- 删除判据编号（`#1`~`#26`）在正文中的引用，改为清单条目的自然语言描述

### 清单形态

清单必须满足三条，缺一条即不合规：

1. **每条是一个"看一眼"的动作**（眼睛能完成的检验），不是需要数数的阈值
2. **不含任何可"凑"的配额数字**（凡"至少 N 张""≤ M%"一律不出现）
3. **含两条元规则**：
   - 「换一双眼睛」固定项（另起 agent 或人工读一遍，只问"哪一篇最假"）
   - 「红线词表写前过一遍」（第一道防线，不是事后检查）

**清单条目示例**（用于对齐形态，非最终文案）：

```
□ 把封面遮住只读标题：能不能猜出封面写了啥？猜得到 = 标题在复述
□ 把这批所有正文首行单独抽出来排成一列读：有哪句像同一个模具倒的？
□ 从后往前读每篇最后一行：有没有连着几篇是同一个收尾手势？
□ 读一篇：哪一句你会想接话？一句都没有 = 这张没钩子
□ 把这批标题放一起：有没有两句其实是一句？
□ 破损/认命档的卡，一个字都不许调笑（硬要求）
□ 交给另一个 agent 读一遍，只问一句：哪一篇最假？
```

### 保留的两个生成器

- **工作包生成器**：把已选结果的素材 + 本测试红线 + 硬指标 + 骨架压成一个文件。保留；但其「硬指标清单」一节须由门禁判据表改写为清单的读者视角动作，并删掉"写完跑门禁"类指令。
- **分配表生成器**：把跨卡配额按拉丁方轮转一次排死。保留；但须删掉被删配额项（短行占比、乙类占比、单型占比、主展开型、末行齐整、末行取值/极差、句号密度），并删掉"须经预检才许动笔"的指令。

### 并行能力处置

保留：串行/并行两种模式的分工、"1 worker = 1 结果 × 四模式"的切分协议、分片任务说明模板。
删除：`--shard` 参数及其"全批级判据降级为 ⚠️"的整套逻辑（该逻辑是为"全批级判据"发明的；判据删除后无意义）。

### 合规检查收敛

`xhs-note-analyzer` 的词库与流程调整：

- 词库补齐本业务医疗词（当前 10 缺 7）
- 增加「批量扫」口径：整批一次审、汇总报告，不逐篇回问
- 明确它成为本技能唯一的独立检查者，且**其覆盖范围从"通用账号运营合规"扩展为"通用合规 + 本业务医疗红线"**

### 删除后的验证替代方案

随脚本删除，原有三条验证手段（`--selftest` 判据回归、`--lint-docs` 全库指针扫描）一并消失。替代为**四项一次性验收**（见 Testing Decisions）。

### 「换一双眼睛」升级

自我评审偏误在无机器兜底后成为主要风险。故「另起一个 agent 读一遍」由可选升为**清单固定项**。

### 体量目标

| | 现状 | 目标 |
|---|---|---|
| 脚本（5 个） | 157.2 KB | ~71 KB（3 个） |
| 文档（SKILL + 6 册） | 91.3 KB | ~66 KB |
| 合计 | 244.8 KB | ~137 KB |
| 执行步骤 | 9 步 | ~6 步 |

> 体量为**目标而非承诺**，以实际改写结果为准。

## Testing Decisions

### 什么是好的验收（本项目适用口径）

本项目是「文档 + 节点脚本」构成的能力包，**没有单元测试缝**。可自动验的只有三类外部行为：

1. **脚本的 CLI 契约**（能否跑通、产物是否可读）
2. **文件系统事实**（引用是否存在、指针是否可达）
3. **字符串事实**（词库是否收齐某组词）

**不可自动验的**：清单本身的质量、清单是否真被执行。这两项**明确靠人判**，不新建工具去兜——新建工具就是重蹈"为维护冗余而生工具"的覆辙。

### 四项验收

| # | 验什么 | 怎么验 | 通过线 |
|---|---|---|---|
| 1 | 无悬空引用 | 全库扫对被删事物的引用（两个脚本名、`--selftest`、`--lint-docs`、`--shard`、`#1`~`#26` 判据编号） | 命中 0 |
| 2 | 指针完整 | 扫所有 md 相对链接，逐个确认目标存在 | 悬空 0 |
| 3 | 生成器仍可用 | 端到端跑两个生成器（同一种子） | 产物可读、无对已删项引用 |
| 4 | 词库覆盖 | 核 10 个本业务医疗词是否全在 analyzer 词库 | 10/10 |

### 缝合点（seams）

**只用一个缝，且是现有的最高缝：生成器 CLI**。

理由：本改造的产出物是"文档 + 生成器产物"，而生成器 CLI 是唯一端到端可验证的接口——它能同时证明「脚本没被改坏」与「产物里没有过期引用」。其余三项验收是**一次性文件系统检查**，不构成需要长期维护的测试缝。

**明确不新建缝**：不建"清单合规性检查器"，不建"判据残留扫描器"（后者用一次性脚本即可，用完即弃）。

### 先验（prior art）

- 上一轮 `文案技能提速` 的 PRD 中，验收方式为「`--selftest` 41/41 + `--lint-docs` 悬空 0 + 靶子仍报 ❌ + 测速」。本次改造**删除前两条载体**，故改为一次性四项验收。
- 靶子（某测试 24 卡必须仍报 ❌）这一"防判据被削弱"的机制**随判据一起退场**——这是本次改造接受的代价（见 Further Notes）。

---

## Out of Scope

- **不动流水线技能**（`xhs-auto-operator-v7` 等）——`xhs-note-analyzer` 是唯一例外，因其在本次改造中承接合规检查职责
- **不改测试产品代码与数据源**（`lib/*.ts` 等）
- **不动已发布的发帖文案**（`design/product-docs/*/docs/*发帖文案.md`）
- **不碰 `.gitignore`，不做任何 git 写操作**（add / commit / reset / checkout）
- **不解决老待办**：`.agent/skills/` 未纳入版本控制（独立小工单）
- **不重做上一轮已完成的生成器主体逻辑**（本改造只做去门禁化的连带修改）
- **不补做上一轮未完成的工单 06/07**（C 全量口径改造、回归测速）——它们基于"有门禁"的架构，本次改造后部分前提已变，需重新评估
- **不为清单新建任何自动检查工具**

## Further Notes

### 这次改造接受的代价（不瞒）

1. **丢掉一层机器兜底**：若本业务医疗词被执行者看漏，防线从两道（写前约束 + 机器扫）降为两道（写前约束 + analyzer），但**第二道从"必然执行"变为"记得执行"**。
2. **指针完整性从"每次自动扫"退化为"本次人工核一次"**：后续若再有文档增删，无工具兜底。
3. **"防判据被削弱"的机制消失了**：上一轮靠"靶子必须仍报 ❌"来防止判据被悄悄放松；判据既已删除，该机制无对象。这意味着**将来若重新引入判据，没有历史基线可比**。
4. **清单可能被跳过**：机器判据一定会执行，清单靠自觉。这是本方案最大的行为学风险。
5. **理论依据已做一次实测（2026-09-21，24 卡）**——见下节。结论：**机制方向成立，但实施时犯了分类错误**。

### 实测结果（2026-09-21 · 性格城市匹配 24 卡 · P2）

| 项 | 数据 |
|---|---|
| 总耗时 | **~12 分钟**（其中 **6 分钟是本文档造成的整篇重写**） |
| 返工轮数 | 3 轮（第 1 轮 24/24 全改 · 第 2 轮换眼睛 3 张 · 第 3 轮 analyzer 12 处） |

**机制验证为真的部分：**

- **「换一双眼睛」真管用**：子代理起子代理、只问「哪一篇最假」→ 点名 3 张、改了 3 张，并指出**点名里 2 张是"模式一"，模式一是这批最弱的一组**。这类判断原 `gate.js` 结构上不可能发现。
- **检查者收敛到 analyzer 有效**：抓到 11 张 / 12 处，其中**绝对化用语 ×6、标签含中危词 ×2 是原 26 条门禁完全没覆盖的平台风控项**（`最好`/`第一条`/`第一年`/`绝对`）。
- **清单条目「正文每一行有没有挤满」抓到 24/24**——它正是 `#4` 的清单化版本，反证了这条判据是"看得出"的物理规格，不是"要数"的配额。

**机制被证伪/需警惕的部分：**

- 三条清单条目实测**0 命中**（遮住封面读标题 / 遮住正文读封面 / 逐篇读末行）。前两条对"甲类字面重叠"的卡天然失效；第三条因分配表已把末行错开而无事可做。**决定暂留**（双保险，无害），但不再视为主力条目。
- 原测速口径**不可与 P1 直比**：P1 是 4 分片并行且含 `gate.js`，P2 是串行单代理无门禁。**去掉门禁本身没有让它变慢——是漏内联规格让它慢了一倍。**

### 本次回归的处置（2026-09-21 已修）

1. 工作包新增 **§4.0「先记这五条硬规格」**，把五条物理规格内联到执行者唯一读到的文件里，并明写「本文档不得删规格、只许删配额」；
2. `03_红线与门禁.md` 新增 **§7.0** 同样五条，使 `01` 里「见自检清单 §7.3」的委派重新有效；
3. `01` 写作口径 / `03` 检查真源 / 工作包内联副本**三处口径恢复一致**；
4. 工作包内联画像原文时，把自指「本文件 §X」改写成「本测试画像 §X」——**修掉原悬空指针**；

### 理论依据（对话中已确认）

- **Deming**：「停止依赖检验来获得质量。取消大规模检验的需要，第一次就把质量做进产品里。」——支持删除事后校验、保留"质量做进去"的生成器。同时，代理指标精确化会诱发"为指标而生产"，与 P1 实验观察一致。
- **Ousterhout**：复杂度是累积的，每一处小复杂单独看都能辩护，堆起来就没人看得懂。5 个脚本 → 3 个、9 步 → 6 步即为收口。
- **自我评审偏误**：有实证的失败模式，机器不是它的解，**换一双眼睛才是**。

### 关键判断（本次改造的核心命题）

> **一条判据若细到非用代码执行不可，说明它依赖精确计数或全批统计——而"必须靠代码判"与"读者看不出"几乎是同一批判据。**
>
> 因此正确处置是**删除这些判据**，而不是换一种方式执行它们。
