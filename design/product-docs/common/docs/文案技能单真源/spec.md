# 文案技能单真源 · PRD

> 项目代号：`文案技能单真源`
> 上游：`文案技能重构`（01~08 done）、`文案技能提速`（01~05 done，06/07 未完）、`文案技能去门禁`（01~07 done）
> 状态：需求对齐与计划**均已获批准**，本 PRD 为实现依据
> 缘起：按 `writing-great-skills` 的失效模式对技能做了一次全面审查（2026-09-22），本 PRD 只做其中 **P0 + 职责/披露两维度** 的结论

## Problem Statement

从使用者（大哥）视角，技能**功能上已经合格、结构上正在自蚀**：没有任何一处是"写得不好"，全是"同一个意思写了第二遍"。而"写第二遍"这件事，已经在一次实测里被证明**会漂、且漂得很快**。

1. **手抄副本已实证漂移（不到一小时）**。`make-workpack.js` 把自检清单、四模式骨架、四个 0 词表**手抄进了代码**，而不是从分册读取。刚修完的同一规则，两处已是两种措辞：`03_红线与门禁.md` 写「合计数 ≤20」，生成器写「总字数 ≤20」；`01_双位与正文.md` 写「异源，与封面零共字——本 SOP 的首选」，生成器写「是首选——与封面零共字，标题位一点不浪费」。

2. **每个机器常量都有一个人类孪生体，且没有一个是权威**。行宽上限「15 字」同时存在于 `skill-data.js`（`LINE_MAX`）、`01`（2 处）、`03`（2 处）、工作包（1 处）；钩子词库同时存在于 `skill-data.js`（`HOOK`）与 `04 §6.3`（10 行引号例句）。代码里的注释自己都在互相矛盾：同一段注释既说真源是 `skill-data.js`、又说真源是 `03`；另一处还写着「与清单逐字同源」——**这是一句无人执行的同步承诺**。

3. **`SKILL.md` 自己违反自己**。第 50 行立规「走工作包 + 分配表流程时**不读**分册」，而同一文件里 6 步表的「去哪」列有 2 格、章节地图的「时机」列有 4 格**都在让执行者去读分册**。这与上一轮造成 **6 分钟整篇重写** 的 bug 是**同一个**（工作包 §0 说不读、§4 又说去读 `01`），只是高了一层。

4. **`05_示例库` 被判「不读（会串味）」却又被热路径指向**。`SKILL.md` 章节地图要「写某个模式前」读它，第 50 行禁止读它，`02_四模式.md` 两处（第 3、14 行）指向它——而 02 正处在「定模式时」这条热路径上。

5. **一名二义、三文件认领**。`§六` 在 `SKILL.md`（流水线）、`00_画像与档位.md`（流水线）、`04_分发与排期.md`（分发排期）各有一个含义；而 `SKILL.md` 的 §六 表里写着「见 **04 §六**」——一张自称 §六 的表在引另一个 §六。

6. **文件命名与职责错配**。`00_画像与档位.md` 承载了整个流水线步表；`03_红线与门禁.md` 的名字里「门禁」**已作废**（属 sediment）；`04_分发与排期.md` 承载 §五 变现网关；`05_示例库.md` 无任何 § 编号，不在全局编号体系内。

7. **分册之间是"全连接网状"而非梯子**。`01` 指向 6 个目标、`00`/`04` 各 5 个、`03` 4 个——读任何一册都会被要求再读 4~6 册。渐进式披露的前提是自上而下的梯子，网状结构直接摧毁了"读一处就知道下一步读哪"的收敛性——这是"读 8 分钟文件"返工的结构根因。

**使用者原话**：「目前这个技能还有哪里需要优化的吗」「检查技能是否职责明确，是否渐进式披露写法」

---

## Solution

三条主线，一句话一条：

1. **单一真源（single source of truth）**：机器需要的人类规则**不再手抄**，改为运行时从带标记的分册切片抽取。改 `03` 一句话，重新生成的工作包自动跟上。
2. **一名一义（one name, one meaning）**：`§` 编号、文件命名与职责三者对齐，一个 § 号只有一个含义。
3. **梯子而非网状（ladder, not mesh）**：`SKILL.md` 的阅读指引与它自己的禁令**只允许一种口径**；不留「既说要读又说不读」的第三态。

关键取舍：**让 md 成为真源，让机器去读它**——而不是让机器成为真源、让 md 去迁就机器。理由是 md 是人和 AI 都在读的东西，它必须保持可读；抽取标记是 HTML 注释，天然对读者不可见。

## User Stories

1. 作为文案生成者，我想在改完 `03_红线与门禁.md` 的自检清单后**不必再去生成器里同步一遍**，以免两处措辞漂开而我只发现了一处

7. 作为文案生成者，我想让 `SKILL.md` 里「不读分册」这条规矩与它下面的表格**不再互相打架**——否则我会像上次一样白写一遍
8. 作为文案生成者，我想明确知道 `05_示例库.md` **到底读还是不读**，而不是在三处看到三种答案
9. 作为文案生成者，我想在读 `SKILL.md` 的 6 步表时，「去哪」列**只给我下一步真正要读的那一处**

11. 作为文案生成者，我想让流水线步表**只有一份**，而不是在 `SKILL.md` 与 `00_画像与档位.md` 两处互为镜像
12. 作为文案生成者，我想让文件名**如实说明它管什么**，以免我按名字找错地方
13. 作为文案生成者，我想让 `03` 的名字不再含已作废的「门禁」字样，以免我以为还有一套机器门禁在跑
14. 作为文案生成者，我想让 `05_示例库.md` 被纳入编号体系或明确标为附录，以免它成为一个"谁都在引、却没人认领"的节点
15. 作为文案生成者，我想让章节地图**把参考资料和可执行脚本分开**，因为这是两种不同的东西
16. 作为文案生成者，我想让「钩子原句整句照抄」这条要求有**一个统一的说法**，而不是在三个文件里各说一遍
17. 作为文案生成者，我想让 `SKILL.md` 里 **13 处「停机／问用户」收敛到闸门那一节**，以免同一纪律散落各处
18. 作为维护者，我想在改动真源后有一条**可执行的验证路径**（改一处 → 重生成 → 改动出现在产物里），而不是靠人记得核对
19. 作为维护者，我想让「哪些规则是机器抽取的」在分册里有**显式标记**，以便新增规则时知道要加标记
20. 作为维护者，我想在新增一条机器需要的规则时**不再需要改两个文件**

## Implementation Decisions

### 一、抽取机制（本项目的技术核心）

**决定：在分册 md 里用 HTML 注释标记规则的起止，生成器在运行时读文件、抽切片、内联。**

形态（示意，标记名待实现时定）：

```
<!-- xhs:extract checklist -->
- [ ] 清单条目……
<!-- /xhs:extract checklist -->
```

三条设计约束：

1. **标记必须是注释**——人读 md 与 AI 读 md 都不该看见它，渲染后也不该出现；
2. **抽取失败必须硬失败**——标记缺失或切片为空时报错退出，**不许静默内联空内容**（静默内联会让执行者以为"这批没有清单"，比报错更危险）；
3. **一个切片只服务一个用途**——不搞一个标记被多处复用，以免将来拆不开。

**为什么不让机器做真源、md 去迁就**：md 是人与 AI 共同阅读面，必须保持可读；且上一轮的教训是"生成器的副本会漂"，把真源放在机器侧只会把漂移方向反过来。

### 二、单一真源的具体边界（哪些收、哪些不收）

| 对象 | 现状 | 决定 |
|---|---|---|
| 自检清单（25 条） | `03 §七` 与生成器**双存**，已漂 | **收**：`03` 为真源，生成器抽取 |
| 四模式与展开五型骨架 | `01`/`02` 与生成器**双存**，已漂 | **收**：分册为真源，生成器抽取 |
| 四个 0 词表 | `03 §7.2` + `skill-data.js` + `analyzer/sensitive-words.md` **三处** | **收**：写作侧以 `03` 为真源；`skill-data.js` 改为抽取；`analyzer` 侧**划边界**（见下） |
| 行宽上限（15 字） | `skill-data.js` + `01`(2) + `03`(2) + 工作包(1) **四处同值** | **收**：`01 §一.2` 为写作口径真源，`skill-data.js` 抽取；`03`/工作包引用 |
| 钩子词库 | `skill-data.js`(`HOOK`) + `04 §6.3` 形态表 | **收**：`04 §6.3` 为真源，`skill-data.js` 抽取 |
| 情绪档位（`MOOD_TABLE`） | `skill-data.js` + `00 §2.4`/`§2.4.1` | **收**：`00` 为真源，`skill-data.js` 抽取 |
| 结果素材、发放率 | 数据源 `lib/*-data.ts` | **不收**：本来就是单一来源 |

### 三、与 `xhs-note-analyzer` 的职责边界

**决定**：**两个不同的检查时点，各有一份按其用途裁过的词表，且明确声明互不派生。**

- `03 §7.2` = **写前守**（正向写作约束，含"为什么"列、含替换建议），面向动笔的人；
- `analyzer/sensitive-words.md` = **交稿后扫**（对抗姿态，含风险分级），面向独立检查者。

**但必须消掉的**：现在 10 个医疗词两处都有、而封杀词／测试术语只有 `03` 有——**部分重叠等于谁都不是权威**。决定改为：**两份词表各自声明覆盖范围，重叠部分只由 `analyzer` 一份承担扫描责任，`03` 侧改为指向声明**。

### 四、命名空间与职责对齐

- **`§六` 一名一义**：流水线独占其 § 号；`04` 的分发排期另编一个 § 号，两处一并改
- **流水线步表只留一份**（`SKILL.md`），`00` 改为指针，删其镜像表
- **`03` 正文标题去掉已作废的「门禁」字样**，文件名与内容对齐
- **章节地图拆两张**：`references` 一张、`scripts` 一张
- **`05_示例库.md` 纳入编号或显式标为附录**，不再做无编号的悬挂节点

### 五、矛盾指针定死为一种口径

**决定：承认「工作包流程要读分册」，删掉禁令；同时把「去哪」列收敛为单点。**

理由：工作包**确实**没内联全部内容（如 `01 §一.2` 的行宽理由、`04 §6.3` 的钩子形态表），强行宣称"全都不读"就必然出现这次的矛盾。**与其维持一个做不到的禁令，不如精确声明要读哪一节。**

- 6 步表「去哪」列：每步**只给一个必读点**，其余降为"需要时"
- 章节地图「什么时候读」列：与步表口径一致，删掉与禁令冲突的表述
- `05_示例库.md`：**定死为"不读"**（工作包 §5 已内联骨架，读它只会串味），删掉章节地图的"写某个模式前"与 `02` 的两处指向

### 六、关键词收敛

- 「钩子原句整句照抄／不许改写／不许砍成共用前缀」→ 收敛为一个 leading word（如 **钩子照抄**），跨 3 文件的 3 处改写为引用
- `停机`（7 次）／`问用户`（6 次）在 `SKILL.md` 的重复 → 收敛到闸门章节一处，其余引用

### 七、不做的事（明确划出）

- 分册间 20+ 交叉指针的**网状结构不动**（需单独评估）
- 不引入任何新判定脚本（守上一轮去门禁成果）
- `description` 瘦身、作废形态否证、开头 no-op 半句等 **P1 项留待下一批**
- `analyzer` 词库主体不碰，只划边界
- 不改测试产品代码与数据源

## Testing Decisions

**缝合点（seam）只有一个，就是生成器产物。**

这是本项目最重要的测试决定：不要去测"文档写得对不对"（无法自动判），而要测**"改真源 → 产物是否跟上"**——这正是本项目要消灭的那类 bug 的可观测形式。

**测什么算好**：只测外部行为 = 「给定分册内容，工作包文本里出现了什么、没出现什么」。不测实现细节（不测用哪种标记语法、抽取函数叫什么）。

**三类测试**：

1. **抽注检验（核心，每笔工单必跑）**：在真源里插入一个唯一哨兵串（如 `ZZTEST-<工单号>`）→ 重新生成工作包 → 断言哨兵**出现在**产物的对应切片位置 → 撤销哨兵。反向亦测：把真源某句改成另一个唯一串 → 断言产物里**旧串已消失**。
   - 这条测试的价值在于：它**无法被手抄副本通过**——手抄副本永远不会跟着真源变。它是本轮唯一能证明"单一真源已建成"的检验。
2. **抽取失败路径**：临时移除一个抽取标记 → 生成器**必须以非零码退出并报出缺失的标记名**（断言不许静默内联）。
3. **不回归**：`make-workpack.js` 退出码 0 且体积 ≤20000 字符；`link-skills.js --check` 通过；全库 md 相对链接全部可达；全库无 `gate.js` / `plan-gate` / `--shard` 残留。

**本轮不做的测试**：不做 A/B 文案质量对照（与结构改造无关，且上一轮已放弃该口径）；不重跑 24 卡测速（另起一次实测才能确认，不在本 PRD 范围）。

## Further Notes

### 本项目的判据（一句话）

> **同一个意思，全技能只允许存一处。** 机器需要它，就去读人写的那一处。

### 与上游项目的关系

- `文案技能重构`（01~08 done）：建立了独立技能、单真源**理念**、门禁判据、三副本 junction。本轮**继续它的"单真源"方向**，但把范围从"词表"扩到"清单、骨架、机器常量"。
- `文案技能提速`（01~05 done）：建立了工作包与分配表两个生成器。**工作包正是本轮漂移的现场**——它是"内联"这个动作第一次被执行的地方，但当时用**手抄**实现，本轮改为**抽取**。
- `文案技能去门禁`（01~07 done）：删掉了两个校验脚本、把清单从"机器判据"改为"人读清单"。本轮**不动这个方向**，只把清单的副本关系理顺。

### 上一轮实测留下的伏笔（本轮相关）

- 上一轮实测唯一触发整篇重写的根因，是**工作包漏内联两条物理规格**（行宽、封面错落）。修法是在三个地方各写一遍——**这恰恰制造了本项目要消灭的四处同值**。本轮把它收敛为单一真源，正是对上一轮修法的结构改进。
- 因此本项目的验收除了"抽取生效"，还要确认**这两条物理规格在各处仍一致**（收敛后应只剩一处真值）。

### 本轮的已知风险

1. **抽取机制让生成器更依赖 md 的结构**——若有人重排分册、误删标记，生成器会硬失败。这是**故意的**（比静默内联空内容好），但需要交接说明。
2. **`skill-data.js` 改为抽取后，生成器启动时多一次文件读**——影响可忽略（毫秒级），但要注意缓存写法别把内容写死。
3. **`§` 重编号会波及老文档**——老卡片与老文档里引用的 `§六` 可能失义。决定：**保留旧号可查（在标题里注明"原 §X"）**，不让历史引用变成哑指针。
