# SPEC — 每测试一次性预计算文档（画像扩充）

## Problem Statement

生成发帖文案时，口音基调、评论区首条、红线清单这三项内容对同一个测试是**恒定不变**的——每个测试的脾气底色不会因为换一批结果就变，评论区首条的承接话术不会变，避开哪些词不会变。但当前 SOP 把这三项都排在写作流水线内部，每次开工都要现场重新推导一遍。

后果有三：一是慢且 CPU 占用高（现场推导属于组合约束求解，不是写作）；二是口音会漂移——同一测试隔几天的两批文案，脾气底色对不上，用户能感觉到不是同一个人在说话；三是红线靠临场记忆，容易漏掉该测试的专属弃用词。

## Solution

把这三项从「每次现场写」改为「每个测试写一次，之后每次直接读」。

落点复用各测试已有的 `docs/测试画像.md`——不新建文件、不搬迁、不删除。画像原本就是「这个测试的常量是什么」的载体，这三项本就是它的同类。画像里没有就按规格补齐后落盘，已经有了就直接读用。

SOP 同步改成**两态判定**：开工读画像时检查三区块是否存在，缺则补齐，有则直接读，不得重新推导。

## User Stories

1. 作为文案操盘手，我想在开工前一眼看到该测试的全量口音表，这样我不用再为每个结果现想「这是个什么脾气的人」。
2. 作为文案操盘手，我想让口音表覆盖该测试的全量结果，这样无论这次走 A 发放率 / B 人工定 6 个 / C 全量哪条路线，我选中的结果都在表里。
3. 作为文案操盘手，我想让口音表从底层结果定义萃取而来，这样口音和结果本身的气质一致，不是外贴的。
4. 作为文案操盘手，我想直接复制评论区首条成稿，这样我不用每次重写承接话术。
5. 作为文案操盘手，我想让评论区首条成稿已经含主页店铺承接，这样转化通道不会在赶工时被漏掉。
6. 作为文案操盘手，我想看到该测试的红线清单三分区摘录，这样我落笔时不用回头翻 SOP。
7. 作为文案操盘手，我想看到该测试专属弃用词逐条列明并配好替代表述，这样我不用临场想替换词。
8. 作为文案操盘手，我想在画像缺区块时有一条明确的补齐路径，这样新测试上线时我知道该怎么建档。
9. 作为文案操盘手，我想在画像已有区块时被明确要求「直接读、不得重新推导」，这样我不会习惯性地又写一遍。
10. 作为 SOP 维护者，我想让画像规格与建档流水线两处表述一致，这样执行时不会遇到自相矛盾的指令。
11. 作为 SOP 维护者，我想让五份画像格式齐平可互换，这样加新测试时能原样复制。
12. 作为 SOP 维护者，我想让机械门禁在画像扩充前后的判定行为一致，这样这次改造不引入回归。

## Implementation Decisions

**模块 1 — 笔记文案篇 SOP 的画像规格改造**

- 测试画像字段表由 8 项扩至 11 项，新增：口音表、评论区首条、红线清单。三项各带区块定义与填写口径。
- 新增读取逻辑条款，落在画像章节内：开工读画像时判定三区块存在性，缺则按定义补齐后落盘，有则直接读用、不得重新推导。
- 【上手：执行顺序索引】第 1 步改写，使「画像没读完不许动笔」的约束覆盖新区块。
- 建档流水线第 1 步同步覆盖新区块。
- 建档流水线第 3 步由「先定口音」改为「读口音表」；仅当画像确无口音表时才触发现场定口音分支。**这是本次改造收益最大的一处**——口音原是按「每测试一次」的频率产生的，却排在了「每批文案一次」的流水线位置。

**模块 2 — 五份测试画像扩充**

- 大女主觉醒测试、恋爱物种领养中心、命定恋人、深度情绪内耗、性格城市匹配，各补齐三区块。
- 口音表须覆盖该测试**全量**结果，不因路线子集不同而缺项。
- 评论区首条为可直接复制的成稿。城市型测试走城市型模板（含相克城市与高能充电日程双钩子），其余走痛点型模板。
- 红线清单 = SOP 擦边红线三分区摘录 + 该测试专属弃用词（逐条配文案侧替代表述）。深度情绪内耗的术语密度最高，须穷尽不得抽样。

**关键约束**

- 素材来源仅限底层结果定义（结果描述 / 金句 / 标签），不读历史发帖文案。零历史依赖铁律不因本次改造松动。
- 骨架矩阵**不入库**。它是每批文案变动的，不属于常量。
- 五份画像已全部存在，本次是原地扩充，不新建文件。

## Testing Decisions

**接缝选择：复用现有门禁自检脚本，不新增测试设施。**

- 好的验收标准是**行为可观测**：画像扩充后，机械门禁对同一批文案的判定应与扩充前一致；五份画像的字段表应逐项对齐 11 项规格。测试的是产出物形态，不是 SOP 的措辞。
- 回归方式：五个测试各跑一次现有门禁自检脚本，确认全绿无灰区，无新增 ❌ 或 ⚠️。
- 人工验收清单：三区块格式五份齐平可互换；口音表条目数 = 该测试全量结果数；专属弃用词逐条有替代表述；评论区首条正文零产品词。
- 不新增测试设施的理由：门禁脚本已覆盖文案侧的机械校验，本次改造不触碰脚本；新增设施会引入需要长期维护的第二套判定标准。

## Out of Scope

- 骨架矩阵落盘或预设
- 修改门禁自检脚本的判定逻辑
- 修改任何历史发帖文案
- 修改底层结果数据源
- 新增测试
- Phase 2 测试研发代码
- 24 张卡的草稿落盘（属 Phase 3 执行，不在本次改造范围）

## Further Notes

- 本次改造的根因是 SOP **按写作流程排列，未按频率排列**。切开频率后可见：口音、评论区首条、红线三项都是「每测试一次」的产物却排在「每批一次」的流水线里；取材配额与型位分配是恒定规则，可预设；只有落笔写句子和跑门禁真正不可提前。后续若要继续优化，应按同一把尺子重新审视剩余步骤。
- 存量画像中的一处已知风险：大女主觉醒测试的某个结果，其原始标签含医疗类词，已在既有画像中标注文案侧不取用。扩充红线清单时须将此类情况固化进专属弃用词，而非依赖记忆。
