# 灵魂归属地：性格城市匹配测试（产品方案 - 34城扩充版）

> **⚠️ 说明**：本方案基于【轻量级单文件架构】策划，目标受众为 15-28 岁的年轻人。本次升级将结果池扩充至**全国 34 个省级行政区（各选 1 个代表城市）**，并通过【多维向量匹配算法】实现更精准、更个性化的测算体验。

## 一、 核心定位与包装
- **测试主题**：你的灵魂究竟属于哪座城市？（性格城市匹配测试）
- **目标受众**：15-28岁年轻人（学生党、初入职场、想要逃离现状或寻找自我的人群）。
- **包装隐喻**：**“一张未知目的地的单程机票” (One-Way Ticket)**
  - 术语替换：
    - 开始测试 -> 【办理登机】
    - 下一题 -> 【航线继续】
    - 上一题 -> 【撤回上一步操作】
    - 生成结果 -> 【打印登机牌】

---

## 二、 算法模型升级：多维向量欧氏距离匹配

由于结果池扩大到 34 个，传统的直接加分法无法做到精细区分。因此采用 **“5维性格坐标系”**：
1. **节奏（Rhythm）**：快节奏(内卷) <-----> 慢节奏(躺平)
2. **环境（Environment）**：繁华都市 <-----> 自然旷野
3. **温度（Temperature）**：冰雪寒冷 <-----> 热带温暖
4. **社交（Social）**：边界感/独处 <-----> 热情/烟火气
5. **口味（Taste）**：清淡养生 <-----> 刺激重口

**算法逻辑**：
- 前端预置 34 个城市的 5 维标准坐标（例如：成都为 `[慢节奏, 繁华, 温暖, 烟火气, 重口]`对应的数值）。
- 用户的初始坐标为 `[0, 0, 0, 0, 0]`，每答一题，对应维度的数值会发生增减。
- 20 题答完后，计算用户坐标与 34 个城市坐标的**欧氏距离**（直线距离），距离最短的即为最匹配的灵魂城市。

## 四、 题库设计（20道生活化题目及维度偏移方向）

*(每道选项均带有隐藏的向量权重调整，如 `Rhythm-` 代表偏向慢节奏)*

**第1题：难得的周末，你最想以哪种方式开启？**
- A. 睡到自然醒，然后点个外卖边吃边刷剧 (Rhythm-, Social-)
- B. 早就预约了网红展/Brunch，打扮精致出门 (Environment+, Rhythm+)
- C. 一个人背上包去附近的公园或山里放空 (Environment-, Social-)
- D. 参加行业交流会或者搞点副业 (Rhythm+, Social+)

**第2题：当你感到极度内耗或焦虑时，通常会怎么缓解？**
- A. 找朋友去酒吧大醉一场，或者去KTV嘶吼 (Social+, Taste+)
- B. 去没有人的自然环境里待着，关掉手机 (Environment-, Social-)
- C. 疯狂搞钱/学习，用充实感覆盖焦虑 (Rhythm+)
- D. 去寺庙烧香，或者坐在街角看大爷大妈下棋 (Rhythm-, Environment+)

**第3题：公司/学校群里发了一个自愿参加的团建活动，你会：**
- A. 只要有得玩就去，顺便认识新朋友 (Social+)

- C. 装作没看见，最烦这种社交活动 (Social-)

**第4题：朋友突然爽约了，你现在一个人走在街上，你会：**
- A. 无所谓，找个咖啡馆坐着发呆，很享受独处 (Social-, Rhythm-)

- C. 觉得浪费时间，不如回家看书/加班 (Rhythm+)

- A. 严格分类，按照效率和功能放进不同的文件夹 (Rhythm+)

**第7题：晚上 11 点，你通常在干什么？**

**第9题：如果在路上碰到流浪猫，你一般会：**

## 五、 产品页面规划与视觉 UI 架构（继承自原版移动端设计）

> **⚠️ 核心架构要求**：所有页面强制适配手机端（必须采用 Tailwind CSS 的 `max-w-md mx-auto` 容器居中方案），确保在任何设备（包括PC浏览器）上都呈现出手机端的极佳质感与交互体验。

### 视觉与 UI 规范（强约束）
- **视觉风格完全继承**：必须 100% 复用原 `city-matching-test` 项目中的顶级 H5 交互设计，包括：
  - 具有真实质感的“打孔车票”悬浮卡片 UI (`.ticket::before/after`)。
  - 动态切换的 5 套主题配色（工业诊断、赛博朋克、东方侘寂、自然旷野、深海治愈），且支持在结果页左右滑动无缝切换。
  - 带有倾斜防伪印章 (`.stamp`) 与条形码 (`.barcode`) 元素的排版设计。
  - 沉浸式的答题过场与题号展示。
- **底层驱动架构**：强制依赖 `TestEngine` (`test-engine.js`) 进行统一的路由管理、历史记录存取以及高质量的截图渲染，抛弃手写的粗糙逻辑。

### 页面流转与强制排版交互规范
1. **首页 (`index.html` 初始层)**
   - 展现原版极简车票样式的检票大厅。测试介绍需阐明（20道题、测试五维灵魂坐标、匹配全国34城）。
   - **强制排版**：首页参与测试的人数必须紧贴放在 **[开始检票] 主按钮的正下方**，人数基数设置在几百到两千之间（追求真实感），文案包装为“目前有 XXX 人正在候机”。
   - 底部固定通往「探索其他路线」和「历史航班记录」的入口。
2. **答题页 (逻辑计算层)**
   - 带有顶部题号进度条，题目与选项保持大字体舒适触控区域。
   - **强制交互**：左上角永远固定为“返回大厅”入口，点击可随时中止测试返回首页。
   - **强制交互**：除第一题外，下方固定显示“撤回上一步”按钮。
   - **强制交互**：最后一题（第20题）在用户点击选项后不能直接跳转，必须在选中后显现明确的提交按钮 **[打印专属车票]**，点击该按钮后才进行跳转和最终结算。
3. **结果页 (单页瀑布流)**
   - **拦截层**：加载出结果后，在最顶层弹出强制订单验证遮罩（订单号拦截系统），输入验证码或订单后方可移除遮罩。
   - 呈现车票大图，支持滑动切换背景主题色。
   - **强制排版**：结果页最上方，必须固定显示“你是本次航班第 XXX 位登机的旅客”。
   - **强制排版**：摒弃单纯的描述文本，必须展示至少 **3个深度解析子维度**，例如：
     1. **【灵魂基调】**（性格的底层逻辑）。
     2. **【城市引力场】**（为什么这座城市最契合你）。
     3. **【人生旷野建议】**（针对用户性格特点的解药式建议）。
   - 页面最下方放置「重新购买机票」和「探索其他路线」按钮。
   - 【长按保存】通过调用 `TestEngine.generatePoster` 生成带图片的高清长按保存遮罩。
