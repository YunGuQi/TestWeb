# 框架版 (Next.js) 性格城市匹配与深度情绪测试：设计与功能对比分析报告

本文档重点分析了位于 `framework-apps/emotional-friction-test` 仓库下的 **框架版** “性格城市匹配测试”（City Personality）与“深度情绪测试”（Emotional Friction）的前端设计与实现逻辑。这两款测试均已从单页面（Single File HTML）升级为基于 **Next.js + React + Tailwind CSS** 的现代化全栈架构，并接入了 CloudBase 云开发后端。

## 1. UI 界面与视觉风格对比

| 对比维度 | 性格城市匹配测试 (组件版 `components-city`) | 深度情绪测试 (应用路由版 `emotional-friction`) |
| :--- | :--- | :--- |
| **框架生态** | 标准 React 组件化（`useState`, `useEffect`）。少量使用 `framer-motion` 用于切题动画。 | 大量引入了 `framer-motion` 实现页面元素的平滑入场（如从底部弹出的历史抽屉）与页面过渡，UI 动效更丰富。此外引入了 `lucide-react` 补充图标体系。 |
| **整体风格** | **车票风 (Ticket Design)**<br>保留了高度拟物化的质感，视觉偏向温和与探索。 | **粗野主义 (Brutalism) + 小票风 (Receipt)**<br>黑白极简，包含高对比的边框 (`border-2 border-black`) 与粗硬的阴影 (`shadow-[4px_4px_0px_#000]`)。 |
| **主题切换** | **支持 5 种主题无缝切换**。在 `ResultView.tsx` 中预置了 5 组 `themeVars`，用户可通过左右按钮修改 `styleIndex` 状态，组件利用 React 数据驱动实时更新内联 `style` 属性以改变主题配色。 | **单一硬核主题**。全局保持统一的暗黑/高对比主题，不支持切换，以传递沉重、严肃的“确诊”氛围。 |
| **核心容器** | 容器引用（`useRef`）在特定的票据卡片上，页面结构采用标准的卡片流。 | 采用“打款小票”设计，边缘使用 SVG/CSS 径向渐变模拟真实小票撕裂的毛边效果。 |

## 2. 核心功能与前后端交互对比

由于升级为框架版，二者在核心数据流上表现出了高度的一致性，但在具体页面的实现上各有侧重：

### 2.1 共同的内容与云端架构
1. **统一的解锁拦截系统 (Paywall)**：
   - 结果页的核心解读内容都被罩上了一层带 `backdrop-blur` 的毛玻璃遮罩。
   - 解锁均需在独立弹窗内输入小红书激活码。其底层均调用同一个后端统一接口 `/api/verify`，仅通过传递不同的 `testId` (`city-personality` vs `emotional-friction`) 进行区分校验。
2. **唯一的 DeviceID 标识**：
   - 为追踪用户，二者都在前端使用了 `crypto.randomUUID()` 生成 `deviceId` 并保存在本地存储中，用于唯一提交答卷和请求解锁。
3. **撤销机制与进度展示**：
   - 答题页均支持“撤回上一题”功能，保留用户的选择状态，且均有题目进度（如 01/20）的文字展示。

### 2.2 不同的数据流向 (SSR vs CSR)
- **性格城市匹配**：
  - 主要依赖 **客户端渲染 (CSR)**。答题结束后，前端直接通过 `fetch('/api/city-submit')` 将用户的 `answers` 数组与 `deviceId` 发送给 API，接口实时计算后返回所属城市及其标签、雷达图坐标等。
- **深度情绪测试**：
  - 深度利用了 **Next.js 服务端组件 (RSC)** 与 Prisma 数据库。结果页 (`result/[id]/page.tsx`) 在服务端直接获取 URL 路由中的 `id`，从数据库（`prisma.testRecord` 等）中读取计算好的分数并注入给客户端组件渲染。

## 3. 各页面 (Pages) 详细对比

### 3.1 封面页 (Landing Page)
- **城市匹配 (`LandingPage.tsx`)**：
  - **排队人数生成**：完全在纯前端通过随机数生成（`1400 + Math.random() * 500`），制造虚拟的热度氛围。
  - **交互与弹窗**：点击历史记录会呼出弹窗，弹窗完全依靠 Tailwind 的纯 CSS 动画 (`animate-[slideUp_0.3s_ease-out]`) 实现抽屉升起，未使用额外动画库。
- **情绪测试 (`page.tsx`)**：
  - **真实的后端统计**：进入首页时通过 `fetch('/api/stats')` 获取数据库中真实的测试人数。
  - **防崩溃与调试后门**：在“当前排队人数”组件上绑定了点击计数器，**连按 5 次将触发清除 LocalStorage 并强制刷新页面**的彩蛋/后门，用于研发调试。
  - **高级动画交互**：历史记录弹窗使用了 `framer-motion` 的 `<AnimatePresence>`，具有弹簧阻尼效果 (`spring`, `damping: 25`)。

### 3.2 答题页 (Quiz Interface)
- **城市匹配 (`QuizInterface.tsx`)**：
  - **数据获取**：客户端发起请求 (`/api/city-questions`) 拉取题库。
  - **答题流转**：选项不带复选框 UI。点击任意选项后，组件立刻触发 `nextStep` 并通过 `framer-motion` 左右平移滑动至下一题。由于是无缝跳转，没有单独的“提交”步骤。
  - **防误触处理**：包含一个原生风格的“确认离开”退出弹窗，未处理浏览器的页面刷新拦截。
- **情绪测试 (`test/page.tsx`)**：
  - **进度条特效**：除数字进度外，页面顶部增加了一个横向填充进度条，且进度条上叠加了一个无限循环的“激光扫描”特效（`animate-[scan_2s_ease-in-out_infinite]`），视觉压迫感更强。
  - **答题流转与 UI**：选项带有字符画风格的伪选框（`[x]` 或 `[ ]`）。
  - **独立的账单打印步骤**：当 20 题全部答完后，**不会自动提交**，而是在页面下方弹出一个巨大的 `[ 打印账单 ]` 按钮，强制用户手动触发 POST 提交。此举更符合“结账单”的主题设定。
  - **严格的防丢拦截**：注册了 `beforeunload` 监听器。如果用户在答题中途不小心点击了浏览器刷新或关闭按钮，浏览器会弹出默认警告防止进度丢失。

### 3.3 结果页 (Result View)
- **城市匹配 (`ResultView.tsx`)**：
  - **图表展示**：5D 灵魂雷达的呈现采用了非常扁平的 HTML Flex 布局，用纯色色块的百分比宽度（`style={{width: ...}}`）模拟雷达柱状图。
  - **组件布局**：页面呈现标准的垂直卡片结构。头部显示“列车班次”、右上角带有红色的“灵魂归属”邮戳 (`-rotate-12`)。
- **情绪测试 (`ResultClient.tsx`)**：
  - **明细账单 (Details)**：支持下拉展开消费明细 (`showDetails` state)，列出题库中触发的每一条负向情绪选项及扣分。这是该测试的核心特色功能。
  - **防伪与视觉层次**：整体卡片通过硬边框和错位阴影强化了立体感；条形码使用了动态计算生成的 `<svg>` 进行渲染。背景印有巨大的水印 `VERIFIED`，排版极度紧凑。

## 4. 截图功能 (Screenshot Generation)

两者均放弃了原生 Canvas，统一引入外部库 `html-to-image` 截取特定的 React DOM 节点（通过 `useRef` 绑定）。但两者的调用参数有所不同，以适应不同的设计需求：

- **性格城市匹配**：
  - 使用 `toPng` 导出为透明背景的 PNG 格式。
  - 配置了 `cacheBust: true` 和固定缩放 `style: { transform: 'scale(1)' }`。由于其圆角和半透明质感，PNG 是更安全的选择。
- **深度情绪测试**：
  - 使用 `toJpeg` 导出为不透明背景的 JPEG 格式。
  - 配置了 `quality: 0.95` 以及 **`pixelRatio: 2`**。由于该测试主要由锐利的直线、纯黑白对比和等宽字体构成，提高像素比和采用 JPEG 可在保证清晰度的前提下极大地减小超大文本图片的文件体积。
