# 发帖文案 · 机读元数据规范（生成器 + 解析器共用）

> 真源对齐：`.scratch/xhs-draft-autofill/spec.md`「机读元数据」  
> 适用范围：`design/product-docs/**/docs/*发帖文案.md`

## 卡块结构

每张卡由以下部分组成：

1. 可选状态行（人工可读）：`> **【状态：已存草稿】**…`
2. 标准 ` ```text ` 块，内含：
   - `[封面]` 起 2～4 行大字
   - `[标题]` 一行
   - 正文若干行
   - 文末恰好 5 个 `#话题`（空格分隔）
3. **元数据行**（紧跟 text 块后，整行包在反引号内）：键值用 `｜` 分隔

## 强制字段（新卡必须写出）

| 键 | 含义 | 示例 |
|---|---|---|
| `cardId` | 稳定卡 ID | `r1_m4` |
| `切片` | 相对 `cards/` 的文件名 | `r1_m4_slice.png` |
| `商品` | 千帆搜索关键词（goodsKeyword） | `大女主觉醒自测模板` |
| `状态` | 空 / `已存草稿(YYYY-MM-DD)` / `已发布(YYYY-MM-DD)` | `已存草稿(2026-10-28)` 或留空 |

推荐顺序：

```text
cardId=<id>｜切片=<file>｜商品=<goodsKeyword>｜状态=<空或枚举>｜结果=…｜模式=…｜…
```

示例（可入队）：

`` `cardId=r1_m4｜切片=r1_m4_slice.png｜商品=大女主觉醒自测模板｜状态=｜结果=内核超稳的满级大女主｜模式=模式四` ``

## 防重

- 元数据 `状态` 为已存草稿 / 已发布 → 默认跳过
- 头部「录入与发布进度看板」中该卡标题已 `[x]` → 默认跳过

## 旧卡

缺 `cardId` / `切片` / `商品` → 解析为 `runnable=false`，控制台标红，**不可入队**。v1 不做批量迁移脚本。

## 生成器义务

`xhs-note-operator` 阶段 1 新卡落盘时必须写出上述四字段；详见技能 SKILL「机读元数据强制」。
