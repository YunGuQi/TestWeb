# 心理测试网站产品文档：你的什么欲望最强？

> 本文档用于指导 AI 或开发者直接制作一个完整的娱乐心理测试网站。
测试主题为「你的什么欲望最强？」
网站不是严肃心理学测评，而是轻松、明亮、愉快、有分享欲的互联网趣味测试。

---

## 1\. 项目定位

### 1\.1 测试名称

**心理测试：你的什么欲望最强？**

### 1\.2 核心体验

用户答完题后，需要产生以下感受：

- 这个测试看起来很轻松，点进去没有压力。

- 题目像生活偏好，不像严肃问卷。

- 答完之后结果有一点准、有一点好笑、有一点被看穿。

- 结果文案有截图欲和分享欲。

- 适合发给朋友互相调侃。

### 1\.3 内容风格

本测试是娱乐向，不是专业心理诊断。

文案风格要求：

- 直白

- 有梗

- 接地气

- 有一点轻微冒犯感

- 不低俗

- 不色情

- 不违法违规

- 不要写成心理学论文

- 不要写成企业问卷

- 不要写成 MBTI 式人格报告

---

## 2\. 网站整体视觉风格

### 2\.1 风格关键词

- 轻松

- 明亮

- 愉快

- 清爽

- 有趣

- 软萌但不幼稚

- 有截图分享欲

- 互联网娱乐测试感

- 朋友圈/小红书分享感

### 2\.2 禁止风格

不要做成以下风格：

- 黑暗

- 压抑

- 恐怖

- 深夜赛博

- 神秘档案

- 严肃心理咨询

- 企业调查问卷

- 医疗心理测评

### 2\.3 推荐配色

页面主色调使用明亮柔和的色彩，不使用大面积黑色、暗紫、暗红、深蓝等压抑色。

推荐方向：

- 奶油白背景

- 浅粉色点缀

- 浅橘色按钮

- 浅黄色卡片

- 薄荷绿色辅助色

- 天空蓝作为小面积强调色

可以使用柔和渐变背景，例如：

- 奶油白 → 浅粉

- 奶油白 → 浅橘

- 浅黄 → 奶油白

- 浅粉 → 浅紫

### 2\.4 页面质感

1. 页面整体使用大圆角卡片。

2. 按钮使用圆角胶囊形状。

3. 卡片可以有轻微阴影，但不要厚重。

4. 选项卡片要有轻微点击反馈。

5. 答题页进度条可以做成柔和渐变色。

6. 结果页可以加入小贴纸、小标签、小图标，但不能太杂乱。

7. 所有页面保持移动端优先，宽度舒适，不允许横向溢出。

## 3\. 网站功能结构

网站需要包含前端页面、后端接口、数据库存储和管理后台，不做纯前端静态页面。

### 3\.1 页面结构

建议页面路径：

- `/` 首页

- `/test` 测试答题页

- `/result/[id]` 测试结果页

- `/admin/login` 管理登录页

- `/admin` 管理后台首页

- `/admin/questions` 题目管理页

- `/admin/results` 结果管理页

- `/admin/results/[id]/preview` 测试结果预览页

- `/admin/settings` 管理设置页

### 3\.2 技术建议

可使用以下全栈方案：

- Next\.js / React

- Node\.js API Routes 或 Express

- SQLite / PostgreSQL / MySQL

- Prisma ORM

- Tailwind CSS

- 移动端优先适配

## 5\. 测试答题页要求

测试共 20 道题，每题 4 个选项，A/B/C/D 单选。

### 5\.1 交互要求

1. 每次只展示一道题。

2. 顶部显示当前进度，例如：`03 / 20`。

3. 显示进度条。

4. 用户选择选项后，需要点击「下一题」进入下一题，避免误触。

5. 支持返回上一题修改答案。

6. 顶部左侧增加按钮：`← 返回首页`。

7. 如果用户还没有开始答题，点击返回首页直接回到首页。

8. 如果用户已经答题，点击返回首页时弹出确认弹窗。

弹窗文案：

> 确定要离开测试吗？当前进度不会保存。

弹窗按钮：

- 继续测试

- 返回首页

用户确认返回首页后，清空当前答题进度并回到首页。

## 7\. 评分与结果判定

### 7\.1 计算流程

用户答完 20 题后，后端根据用户答案累计六个维度分数：

- 禁欲 abstinence

- 爱欲 love

- 情欲 lust

- 食欲 appetite

- 物欲 material

- 占有欲 possessive

后端计算，不要只在前端计算。

流程：

1. 接收用户 20 道题的答案。

2. 查询每道题对应选项的 score JSON。

3. 累加得到 6 个维度分数。

4. 根据判定逻辑匹配最终结果。

5. 生成一条测试记录。

6. 返回结果 id 或测试记录 id。

7. 前端跳转结果页。

### 7\.2 判定优先级

结果判定需要按固定优先级执行，避免多个结果同时命中。

优先级如下：

1. 无欲无求

2. 清心寡欲

3. 深情好色

4. 超强占有欲

5. 情深似海

6. 及时行乐

7. 随心所欲

8. 恋爱上头

9. 野心不小

10. 啥都想要

11. 干饭至上

12. 人间清醒

### 7\.3 具体判定规则

#### 无欲无求

触发条件：

```Plaintext
禁欲是最高分
且 禁欲 >= 24
且 爱欲 <= 8
且 情欲 <= 6
且 食欲 <= 6
且 物欲 <= 8
且 占有欲 <= 8
```

#### 清心寡欲

触发条件：

```Plaintext
禁欲是最高分
且 禁欲 >= 20
且 物欲 <= 12
且 爱欲 <= 12
且 占有欲 <= 12
```

#### 深情好色

触发条件：

```Plaintext
爱欲 >= 16
且 情欲 >= 10
且 禁欲 <= 12
```

附加优先条件：

```Plaintext
如果 爱欲 + 情欲 >= 占有欲 + 物欲
优先判定为：深情好色
```

#### 超强占有欲

触发条件：

```Plaintext
占有欲是最高分
且 占有欲 >= 18
```

附加条件：

```Plaintext
如果 占有欲 >= 爱欲 + 3
优先判定为：超强占有欲
```

#### 情深似海

触发条件：

```Plaintext
爱欲是最高分
且 爱欲 >= 18
```

排除条件：

```Plaintext
如果 情欲 >= 10 且 禁欲 <= 12
优先判定为：深情好色

如果 占有欲 >= 14
优先考虑：恋爱上头
```

#### 及时行乐

触发条件：

```Plaintext
物欲 >= 12
且 食欲 >= 8
且 情欲 >= 8
且 禁欲 <= 10
```

#### 随心所欲

触发条件：

```Plaintext
物欲 >= 14
且 食欲 >= 8
且 禁欲 <= 12
```

排除条件：

```Plaintext
如果 情欲 >= 8 且 物欲 >= 12 且 食欲 >= 8
优先判定为：及时行乐
```

#### 恋爱上头

触发条件：

```Plaintext
爱欲 >= 14
且 占有欲 >= 12
```

排除条件：

```Plaintext
如果 爱欲 >= 16 且 情欲 >= 10
优先判定为：深情好色

如果 爱欲 >= 18 且 占有欲 < 14
优先判定为：情深似海
```

#### 野心不小

触发条件：

```Plaintext
占有欲 >= 14
且 物欲 >= 12
且 爱欲 < 14
```

#### 啥都想要

触发条件：

```Plaintext
物欲是最高分
且 物欲 >= 18
且 食欲 >= 6 或 爱欲 >= 8 或 情欲 >= 6
```

#### 干饭至上

触发条件：

```Plaintext
食欲是最高分
或 食欲 >= 12 且 物欲 >= 8
```

排除条件：

```Plaintext
如果 物欲 >= 12 且 情欲 >= 8 且 禁欲 <= 10
优先判定为：及时行乐
```

#### 人间清醒

触发条件：

```Plaintext
禁欲 >= 14
且 禁欲是最高分或第二高分
且 不满足“清心寡欲”或“无欲无求”
```

### 7\.4 兜底规则

如果以上 12 个条件都没有命中，就按最高分维度兜底：

```Plaintext
禁欲最高 → 人间清醒
爱欲最高 → 情深似海
情欲最高 → 深情好色
食欲最高 → 干饭至上
物欲最高 → 啥都想要
占有欲最高 → 超强占有欲
```

如果最高分并列，按组合判断：

```Plaintext
爱欲 + 情欲最高 → 深情好色
爱欲 + 占有欲最高 → 恋爱上头
物欲 + 食欲最高 → 随心所欲
物欲 + 食欲 + 情欲都高 → 及时行乐
物欲 + 占有欲最高 → 野心不小
禁欲 + 其他欲望都低 → 清心寡欲
```

## 12\. 管理后台要求

### 12\.1 管理登录

路径：`/admin/login`

登录要求：

1. 管理员输入密码进入后台。

2. 管理密码不能写死在前端。

3. 管理密码需要保存在后端环境变量或数据库配置中。

4. 默认开发密码可以是：`admin123456`。

5. 登录成功后设置管理员 session 或 token。

6. 未登录访问 `/admin` 相关页面时，自动跳转到 `/admin/login`。

登录页文案：

- 标题：管理后台

- 副标题：请输入管理密码

- 输入框 placeholder：请输入管理密码

- 按钮：进入管理后台

- 错误提示：密码错误，请重新输入

### 12\.2 管理后台首页

管理后台首页需要包含：

1. 数据概览：

    - 测试题数量

    - 测试结果数量

    - 今日测试次数

    - 累计测试次数

2. 快捷入口：

    - 编辑测试题

    - 管理测试结果

    - 预览测试结果

    - 修改管理密码

### 12\.3 题目管理

路径：`/admin/questions`

功能要求：

1. 展示 20 道题列表。

2. 每道题显示题号、题目标题、四个选项摘要。

3. 点击编辑进入编辑页或打开编辑弹窗。

4. 可以编辑：

    - 题目标题

    - A/B/C/D 选项文案

    - A/B/C/D 选项隐藏计分规则

5. 计分规则用可视化输入，不要要求用户直接写 JSON。

6. 每个选项下展示 6 个维度的加分输入框：

    - 禁欲

    - 爱欲

    - 情欲

    - 食欲

    - 物欲

    - 占有欲

7. 保存后写入数据库，并立即影响前台测试页。

8. 提供恢复默认题目的按钮。

9. 恢复默认题目前需要二次确认。

### 12\.4 结果管理

路径：`/admin/results`

功能要求：

1. 展示 12 个结果列表。

2. 每个结果显示：

    - 结果名称

    - 属性

    - 一句话评语

    - 触发条件说明

3. 点击可以编辑结果内容。

4. 可以编辑：

    - 结果名称

    - 属性

    - 评语

    - 检测结果百分比

    - 完整分析文案

    - 欲望雷达短句

    - 分享短句

    - 触发条件说明

5. 保存后写入数据库，并立即影响前台结果页。

6. 提供恢复默认结果文案的按钮。

7. 恢复默认结果文案前需要二次确认。

### 12\.5 结果预览

管理后台必须提供“预览测试结果”功能。

路径建议：

- `/admin/results`

- 点击某个结果的“预览”按钮

- 进入 `/admin/results/[id]/preview`

要求：

1. 预览页必须复用正式用户结果页的组件和样式。

2. 页面效果必须和用户真实测试完成后看到的结果页保持一致。

3. 预览模式下需要额外显示一个管理栏：

    - 返回管理页

    - 编辑此结果

4. 预览模式下不生成测试记录。

5. 预览模式下不影响统计数据。

6. 不允许只用普通文字展示结果，必须保持正式结果页视觉效果。

### 12\.6 修改管理密码

路径：`/admin/settings`

功能要求：

1. 输入当前密码。

2. 输入新密码。

3. 再次确认新密码。

4. 当前密码正确才允许修改。

5. 新密码需要保存到数据库或安全配置中。

6. 修改成功后提示：密码修改成功，请重新登录。

7. 修改后清除当前登录状态，跳转回 `/admin/login`。

## 13\. 数据初始化要求

项目首次启动时，如果数据库为空，需要自动初始化：

1. 默认 20 道测试题。

2. 默认 12 个测试结果。

3. 默认管理密码。

4. 默认评分规则。

初始化后，管理员可以在后台修改。

不要每次启动都覆盖管理员修改过的数据。只有数据库为空时才初始化默认数据。

## 14\. 安全要求

1. 管理密码不能出现在前端代码中。

2. 管理密码必须哈希存储。

3. 管理接口需要鉴权。

4. 未登录不能访问管理接口。

5. 用户提交答案时需要校验题目数量和选项是否合法。

6. 管理后台编辑内容时需要做基础校验，避免空题目、空选项。

7. 第一版不需要用户登录。

8. 不收集用户姓名、手机号、邮箱等个人隐私信息。

9. 测试记录只保存答案、分数、结果和时间，不保存身份信息。

## 15\. 移动端适配要求

1. 所有页面以手机端体验为优先。

2. 页面最大宽度建议 430px，居中展示。

3. 所有按钮高度不低于 44px。

4. 选项卡片需要有足够点击面积。

5. 不允许横向滚动。

6. 长文案结果页需要排版清晰，分段展示。

7. 管理后台在手机端也要能用，但可以更适配桌面端。

8. 卡片、按钮、弹窗都必须避免横向溢出。

9. 弹窗内容需要设置最大宽度和 `box-sizing: border-box`。

## 16\. AI 建站提示词

以下提示词可以直接给 AI 编程工具使用。

```Plaintext
请帮我开发一个完整的全栈心理测试网站，项目主题为「心理测试：你的什么欲望最强？」。

这个网站不是严肃心理学测评，而是偏娱乐、偏互联网传播、偏“被看穿”的趣味测试网站。整体视觉风格必须轻松、明亮、愉快、清爽、有分享欲，不要做成黑暗、赛博、恐怖、神秘档案风，也不要做成严肃心理问卷。

网站需要包含前端页面、后端接口、数据库存储和管理后台，不要做成纯前端静态页面。

技术方案建议使用 Next.js + React + Tailwind CSS + Prisma + SQLite 或 PostgreSQL。请保证项目可运行、结构清晰、移动端优先适配。

页面路径包括：
- `/` 首页
- `/test` 测试答题页
- `/result/[id]` 测试结果页
- `/admin/login` 管理登录页
- `/admin` 管理后台首页
- `/admin/questions` 题目管理页
- `/admin/results` 结果管理页
- `/admin/results/[id]/preview` 测试结果预览页
- `/admin/settings` 管理设置页

首页需要展示网站标题「你的什么欲望最强？」、副标题「一次不太正经的内心欲望小测试。」、引导文案和「开始检测」按钮。首页不展示管理后台入口。

答题页共 20 道题，每题 4 个选项。每次只展示一道题，顶部显示进度和进度条，支持上一题、下一题。顶部左侧必须有「← 返回首页」按钮。如果用户已经开始答题，点击返回首页需要弹出确认提示：「确定要离开测试吗？当前进度不会保存。」按钮为「继续测试」和「返回首页」。

后端需要保存题目、结果、测试记录和管理配置。用户提交答案后，由后端根据隐藏计分规则计算六维度分数，并根据结果判定逻辑返回最终结果。六个维度为：禁欲、爱欲、情欲、食欲、物欲、占有欲。

结果页需要像一份轻松有趣的欲望检测报告，展示结果名称、属性、检测结果百分比、一句话评语、完整分析文案、六维度雷达或条形图、欲望雷达短句、分享短句，并提供「重新测试」「复制结果文案」「保存结果图/生成分享图」按钮。

管理后台需要密码登录，管理密码不能写死在前端，必须保存在后端环境变量或数据库中并哈希存储。默认开发密码为 admin123456。未登录不能访问管理后台和管理接口。

管理后台需要包含：
1. 数据概览：测试题数量、测试结果数量、今日测试次数、累计测试次数。
2. 题目管理：可以编辑 20 道题的题目标题、A/B/C/D 选项文案，以及每个选项对应六个维度的隐藏计分。计分规则需要可视化输入，不要要求用户直接写 JSON。

4. 结果预览：可以预览每一种测试结果，预览页面必须复用正式用户结果页组件和样式，效果必须和用户真实测试结果页一致。预览模式下不生成测试记录，不影响统计数据。
5. 修改管理密码：输入当前密码、新密码、确认新密码，修改成功后重新登录。
6. 恢复默认题目和恢复默认结果文案功能，恢复前必须二次确认。
```

## 17\. 交付验收标准

开发完成后，网站必须满足：

1. 用户可以从首页进入测试。

2. 用户可以完成 20 道题。

3. 用户可以返回上一题修改答案。

4. 用户可以从测试页返回首页。

5. 用户完成测试后可以看到对应结果。

6. 结果页展示完整文案和六维度数据。

7. 管理员可以登录后台。

8. 管理员可以编辑题目。

9. 管理员可以编辑结果。

10. 管理员可以预览任意结果，且预览效果和正式结果页一致。

11. 管理员可以修改密码。

12. 数据库首次启动能初始化默认数据。

13. 前端用户接口不泄露隐藏计分规则。

14. 管理接口需要鉴权。

15. 手机端无横向溢出。
